# 前　言

十九岁那年我第一次登进机房里的一台服务器。屏幕上的提示符和我笔记本上的一模一样，可它背后那台机器在两百公里之外。那种错位感很久没有散去。我敲下的字符去了哪里，它凭什么把结果送回来，中间经过的那些设备看到了什么。

这件事在今天已经平常到不值得追问。写代码的人把程序放到云上跑，训练模型的人把几万张显卡当成一台机器用，做数据的人把几百 TB 的文件交给一个网址去管。计算离开桌面，是过去五十年里最安静也最彻底的一次变化，而支撑它的那些约定，几乎没有人从头学过。

## 计算是怎么走到别处的

最早的时候，计算机只有一台，放在机房里，谁要用就走到它面前。后来出现了分时系统，一台主机接上许多终端，每个人守着自己的键盘和纸带，看起来像是在独占机器。那时的终端没有算力，只负责显示和输入，真正干活的是远处那台大机器。远程访问的第一层意义在这里就定了型，你看到的东西和真正做事的东西，可以不在同一个地方。

再往后，终端从串口线换成了网络。主机可以躲在防火墙后面，用户可以在另一个城市。这时候出现了新的麻烦。数据要穿过许多不属于你的设备，密码和命令都是明文，任何一台中间机器都能抄一份。SSH 就是为这个麻烦发明的，它把通道加密，把身份验证做在加密之后，还顺手解决了文件传输和端口转发。

第三步是责任的外移。机器不再属于你所在的团队，它属于云厂商；数据不再放在自己的磁盘上，它存在对象存储里；运维不再由每个人各自进行，而是被收拢到一台专门的设备上，留下记录。技术问题于是变成了管理问题，谁能进、能做什么、做完留下什么证据，这些都需要机制来回答。

这三步留下的东西叠在一起，就是今天你面前的工具箱。终端里的 `ssh`，编辑器里的远程开发，公司要求必须经过的堡垒机，浏览器里那个像网盘一样的存储控制台。它们看起来属于四个不同的产品，其实是同一组问题在不同年代、不同层面的答案。

## 这套东西为什么难懂

因为这些机制被刻意藏在了里面。好的工具会把复杂度吃掉，只把最常用的那一条路铺平。你敲一条命令就能进服务器，点一个按钮就能连上远端项目，拖一个文件就能上传。操作越简单，藏在下面的东西越多。

麻烦在于，一旦你偏离了那条铺好的路，就完全没有线索。配置里多出一行看不懂的参数，报错里出现一个没见过的单词，连接在某个阶段停住不动，这些时刻没有任何提示告诉你该往哪里想。于是只能试，试对了算运气，换个环境又不灵。我自己的例子是端口。早年在机房给一台机器装驱动，网线插好，地址配好，`ping` 得通，`ssh` 就是连不上。折腾了半个多小时才发现对端 sshd 监听在 2222，而我一直往 22 敲。那时候我并不知道端口是什么，只知道要加一个 `-p`。这种经验很脆，风一吹就散。

这类困惑有个共同点，它们都是机制在表层留下的痕迹。用户名里出现两个 at 符号，是堡垒机把三层身份压进了一个字段。`.pem` 和 `id_rsa` 名字不同，是两种编码格式和两种算法被混着叫了很多年。上传文件在浏览器里顺利、在命令行报 403，是签名算法对请求的每一个字节都较真。VS Code 连不上时要看哪段日志，取决于它把哪一部分搬到了远端。这些痕迹分布在不同的层，看不出联系，是因为中间那套结构没有露出来。

这本书要做的就是把那套结构露出来。不按产品讲，也不按操作清单讲，而是按问题讲。每个概念先说它要解决什么，再说它用什么办法解决，最后说它在你的终端、配置文件、报错信息里长什么样。这样安排的好处是，学到的不是几条命令，而是一张能自己往里填细节的地图。

读完之后，你应该能做到三件事。看懂别人给的配置，知道哪一行是关键、哪一行可以删。读懂报错，判断问题出在网络、认证、授权还是签名。判断一份方案是否合理，比如为什么某个端口不该暴露在公网，为什么某个桶不该开公共读。这三件事都不依赖记住具体参数，依赖的是理解机制。

## 这本书假设你会什么

假设你用过 Windows 或 macOS 的电脑，会在终端里敲几条命令，知道文件和目录的区别，写过程序，哪怕只是 Python 的入门水平。不假设你学过计算机网络，不假设你懂密码学，也不假设你管过 Linux 服务器。凡是需要的背景知识，书里都会从头讲起。

书里出现的每一条命令都可以直接运行，除了少数需要真实服务器的地方会用占位符代替。占位符会写成这样 `〈你的用户名〉`，需要你替换成自己的信息。

## 全书的组织方式

全书按四层推进，一层比一层远离键盘。

第一篇讲链路。一条命令从你的手指出发，经过网卡、路由器、运营商的骨干网、堡垒机，最后落到远端的一个进程上。这一篇把这条路上每一段的责任摊开，也把“连不上”这件事拆成可以逐段验证的判断题。

第二篇讲信任。链路通了只说明字节能过去，不说明对面是谁，也不说明中间有没有人偷看。密码学在这里不是装饰，而是 SSH 每一个设计决定的来源。这一篇会把对称加密、非对称加密、密钥交换、哈希、证书按需引入，然后完整走一遍 SSH 的握手、认证与隧道。

第三篇讲控制。一台机器、一个人的时候，信任可以靠熟人关系维持；几百台机器、几十个人的时候，就必须靠制度和技术。堡垒机把分散的凭据收拢，把每次操作录下来。VS Code 的远程开发则把开发环境整个搬到远端，只把界面留在手边。这两件事看起来无关，底下的机制是同一套。

第四篇讲数据。代码跑起来之后会产生数据，数据要存在别人的磁盘上，还要能被下一台机器读到。对象存储的接口简单到只有几个 HTTP 方法，可用起来处处是坑，签名错一个字节就是 403。这一篇把数据模型、分片上传、签名算法与权限体系讲透，最后把四层串成一条完整的链路。

## 关于版本与命令

书里的命令以 OpenSSH 9.x、VS Code 1.9x、JumpServer 3.x、腾讯云 COS 与 AWS S3 的公开接口为准。这些软件都在持续演进，算法默认值、界面文字、命令行参数都可能变化。遇到不一致时，先看 `--help` 和你所用版本的官方文档，再用书里的原理去判断差异。原理的寿命比参数长得多。

书中的服务器地址、用户名、密钥文件名都是示例，不指向任何真实资产。你自己环境里的私钥、密码、访问密钥，任何时候都不要写进文档、截图或者聊天窗口。
