# 前　言

这本书要解决的问题很具体。

你可能已经在用一些东西了。终端里敲 `ssh` 能进服务器，VS Code 里点一下能连上远端的项目，浏览器里打开一个网盘一样的界面能上传下载文件，公司还要求所有服务器操作必须经过一台“堡垒机”。这些工具都能用，但它们的内部对你是不透明的。配置文件里那一行 `User alice@ubuntu@10.0.0.5` 到底是什么意思，为什么用户名里要有两个 at 符号；`.pem` 文件和 `id_rsa` 有什么区别，为什么权限必须是 600；明明在浏览器里上传文件很顺利，用命令行却总是报 403；VS Code 连不上时，到底该看哪一段日志。这些问题不大，却会在关键时刻把人卡住。

卡住的滋味我体会过。早年在机房给一台机器装驱动，网线插好、地址配好，`ping` 得通，`ssh` 就是连不上。折腾了半个多小时才发现，对端 sshd 监听在 2222 端口，而我一直往 22 端口敲。那时候我并不知道“端口”到底是什么，只知道“要加一个 `-p`”。这种靠试错积累起来的经验很脆弱，换个环境就失效。

这本书想做的事，是把这些工具背后的机制讲清楚，让你从“照着做”变成“知道为什么这么做”。知道了为什么，配置错了能自己看出来，报错信息能自己读懂，别人给的指南也能自己判断哪一行是关键。

## 这本书假设你会什么

假设你用过 Windows 或 macOS 的电脑，会在终端里敲几条命令，知道文件和目录的区别，写过程序，哪怕只是 Python 的入门水平。不假设你学过计算机网络，不假设你懂密码学，也不假设你管过 Linux 服务器。凡是需要的背景知识，书里都会从头讲起。

书里出现的每一条命令都可以直接运行，除了少数需要真实服务器的地方会用占位符代替。占位符会写成这样 `<你的用户名>`，需要你替换成自己的信息。

## 全书的组织方式

全书分四篇。

第一篇讲清楚“连接”这件事本身。从一次 `ssh` 登录出发，把经过的网络设备、协议层次和服务器上的进程都摊开看一遍。这一篇结束后，你会知道一条命令从键盘到远端 shell 中间经历了什么，也会知道连不上时该往哪里看。

第二篇讲信任。远程登录最要紧的不是“能连上”，而是“连的是对的那台机器，且中间没人偷看”。密码学在这里不是装饰，而是 SSH 每一个设计决定的来源。这一篇会把对称加密、非对称加密、密钥交换、哈希、证书这些概念按需引入，然后完整走一遍 SSH 协议的握手与认证。

第三篇讲控制。当机器从几台变成几百台，当操作的人从一个人变成一个团队，“能连上”就变成了风险。堡垒机是为了把这种风险收拢起来而出现的设备。我们会拆开 JumpServer 看它的组件与权限模型，也会解释 VS Code 的远程开发到底在你和目标机之间架了什么。

第四篇讲数据。代码跑在服务器上，数据往往放在对象存储里。对象存储的接口是 HTTP，每一次请求都要签名，签名错了就是 403。这一篇会把对象存储的数据模型、签名算法与权限体系讲透，最后把四篇的内容串成一条完整的链路。

## 关于版本与命令

书里的命令以 OpenSSH 9.x、VS Code 1.9x、JumpServer 3.x、腾讯云 COS 与 AWS S3 的公开接口为准。这些软件都在持续演进，算法默认值、界面文字、命令行参数都可能变化。遇到不一致时，先看 `--help` 和你所用版本的官方文档，再用书里的原理去判断差异。原理的寿命比参数长得多。

书中的服务器地址、用户名、密钥文件名都是示例，不指向任何真实资产。你自己环境里的私钥、密码、访问密钥，任何时候都不要写进文档、截图或者聊天窗口。
