# 前　言

远程操作在今天是一件太普通的事。写代码的人把程序放到云上编译，做模型的人把任务交给机房里的一排显卡，整理数据的人通过一个网址管理几百 TB 文件，运维的人要登录到几十台机器上检查状态。这些动作看起来各不相同，底下却是同一组问题：怎么把指令安全地送到远端，怎么确认对面确实是你以为的那台机器，怎么让做过的事留下痕迹，怎么在别人的磁盘上存取自己的数据。

这组问题不是一天形成的。最早的计算只有一台机器，谁要用就走到它面前。分时系统出现后，一台主机接上许多终端，终端只负责显示，真正干活的是远处那台大机器，远程操作的第一层含义在这里定下了。终端从串口线换成网络之后，数据要穿过许多不属于你的设备，明文传输变得不可接受，SSH 就是在这个背景下被发明出来的。再往后，机器归云厂商所有，数据存在对象存储里，运维被收拢到专门的系统上，技术问题开始和管理问题纠缠在一起。

这三步留下的约定叠在一起，就是今天这套工具箱。它们分属不同的年代，回答的是不同层面的问题，所以放在一起看时显得零散。理解了它们各自的来历，零散感就会消失。

## 这本书讲什么

书里讲四层东西。

第一层是链路。一条命令从键盘出发，经过网卡、路由器、运营商的骨干网，落到远端的一个进程上。这一层要回答的是“为什么连不上”，以及怎么把这句话拆成可以逐段验证的判断题。

第二层是信任。链路通了只说明字节能过去，不说明对面是谁，也不说明中间有没有人偷看。密码学在这里不是装饰，而是 SSH 每一个设计决定的来源。这一层要回答的是“凭什么相信”，以及这些信任在什么条件下会失效。它顺带解决了另一个问题：当你不在那张网里的时候，怎么把整张网搬过来，这就是 VPN。

第三层是控制。一台机器一个人的时候，信任可以靠熟人关系维持。几百台机器几十个人的时候，就必须靠制度和技术。堡垒机把分散的凭据收拢，把操作记录下来。远程开发把开发环境整个搬到远端，只把界面留在手边。这一层要回答的是“怎么管住”，以及管住之后付出了什么代价。

第四层是数据。代码跑起来会产生产出，产出要存在别人的磁盘上，还要能被下一台机器读到。对象存储的接口简单到只有几个 HTTP 方法，可用起来处处是坑。这一层要回答的是“怎么存取”，以及为什么一个字节的差异就会得到 403。

四层之间是依赖关系。不懂链路就看不懂信任里的握手，不懂信任就看不懂堡垒机为什么要托管密钥，不懂控制就看不懂远程开发为什么需要端口转发。所以这本书按这个顺序写，每一章都建立在前面几章之上。

## 全书地图

四层落到章节上，是这样分的。

| 篇 | 章 | 这一篇在回答什么 | 读完之后能做什么 |
| --- | --- | --- | --- |
| 第一篇 | 1–4 | 字节能过去吗 | 把“连不上”拆成几个可以分别验证的问题 |
| 第二篇 | 5–9 | 凭什么相信对面，一条通道能承载什么 | 看懂 `ssh -v` 的每一段；会开隧道，也懂 VPN 在改什么 |
| 第三篇 | 10–12 | 几十个人、几百台机器怎么管 | 知道堡垒机在挡什么；明白远程开发为什么这样设计 |
| 第四篇 | 13–15 | 数据存在哪里、怎么取 | 能从错误码定位问题；能把四层串成一条链路 |

第 4 章的位置值得单独说一句。它讲服务器内部，进程、终端、权限、路径、环境变量、日志，看起来离“远程访问”远了，其实是最不该跳过的一章：不懂进程和终端，就看不懂 sshd 怎么把 shell 启动起来；不懂权限，就解释不了私钥为什么必须是 600；不懂日志，就查不出登录为什么被拒。它把“登录之后服务器上发生了什么”讲完，第三篇的堡垒机才有落点。

## 怎么读

每一章的结构是一样的。先说清这一章要解决的问题，再讲解决它的机制，最后落到你在终端、配置文件、日志里实际会看到的东西。机制部分是重点，操作部分是它的自然结果。如果只想要命令，附录 A 有速查表，但那份表单独看没有多大价值。

书里的图和表都服务于理解，不追求覆盖所有细节。图注写在图的下方，正文会在需要时引用编号。代码块只放能直接运行或者能直接粘贴的内容，注释用英文，避免等宽字体缺字。

阅读时建议手边有一台可以折腾的机器。很多概念看起来抽象，实际敲一遍就清楚了。比如把 `ssh -v` 的输出从头读到尾，比读三页协议描述更有效。书里会指出哪些输出值得逐行看。

书按依赖顺序排，从头读最省力。如果只想先解决眼前的问题，可以按三条路线挑着读：

- 连不上、卡住、报各种错：第 2、3、4 章，再跳到第 6、8 章看协议与隧道
- 要在企业环境里干活：2.4 节，加上第 10、11、12 章
- 要处理训练数据与模型：第 13、14、15 章，需要时回看第 7 章

三条路线都能独立读通：关键概念第一次出现时都给了足够解释，临时查名词翻附录 B，查命令翻附录 A。

## 这本书假设你会什么

假设你用过 Windows 或 macOS 的电脑，会在终端里敲几条命令，知道文件和目录的区别，写过程序，哪怕只是 Python 的入门水平。不假设你学过计算机网络，不假设你懂密码学，也不假设你管过 Linux 服务器。需要的背景知识，书里会从头讲起。

如果你没有系统学过 Linux，第 4 章会把最需要的常识补齐：进程与 fork、终端与伪终端、文件描述符、用户与权限、路径、环境变量、日志。

占位符写成 `〈你的用户名〉` 这样的形式，需要替换成你自己的信息。书里出现的地址都是文档专用地址段，不对应任何真实资产。

## 关于版本

书里的命令以 OpenSSH 9.x、VS Code 1.9x、JumpServer 3.x、腾讯云 COS 与 AWS S3 的公开接口为准。这些软件都在持续演进，算法默认值、界面文字、命令行参数都可能变化。遇到不一致时，先看 `--help` 和你所用版本的官方文档，再用书里的原理去判断差异。

原理的寿命比参数长。十五年之后，具体的加密算法可能换了一轮，配置文件里可能多出几个新选项，但这本书里讲的分层、认证、授权、审计、签名，仍然会是理解新工具的那把钥匙。
