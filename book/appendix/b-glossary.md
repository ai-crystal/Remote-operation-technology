# 附录 B　术语表

**SSH**　Secure Shell，一套用于在不安全网络上安全访问远端主机的协议族，由传输层、用户认证层、连接层三个子协议组成。

**sshd**　SSH 的服务端程序，通常在 22 端口监听，接受连接、完成认证、分配会话。

**OpenSSH**　最广泛使用的 SSH 实现，包含客户端 `ssh`、服务端 `sshd`、密钥工具 `ssh-keygen` 等。

**公钥认证**　客户端用私钥对一段包含会话标识的数据签名，服务端用对应公钥验证，从而确认客户端持有私钥。

**密钥**　能用于加密、解密或签名的一段数据，通常是一长串随机数。非对称的一对里分公钥与私钥，对称加密只有一把。

**私钥**　只能由持有者保存的密钥，用于签名或者解密，权限必须是 600。

**公钥**　可以公开分发的密钥，用于验证签名或者加密，以一行文本形式存放在 `authorized_keys` 中。

**签名**　用私钥（或共享密钥）对数据算出的值，对方用对应的公钥（或同一把密钥）能验证它出自谁手、内容有没有被改。

**指纹**　对公钥做哈希得到的短字符串，用来快速比对两把公钥是否相同。

**known_hosts**　客户端记录见过的服务器主机公钥的文件，用于检测主机身份变化。

**TOFU**　Trust On First Use，首次使用即信任，第一次连接时记录主机公钥，之后比对。

**证书**　由 CA 签发的一份声明，把一把公钥和某个身份绑定起来，并写明有效期。

**主机密钥**　服务器用于证明自己身份的一对密钥，安装 sshd 时自动生成。

**authorized_keys**　服务端文件，列出允许登录的公钥，每行一把，可在行首加限制选项。

**ssh-agent**　后台进程，保管解密后的私钥，替客户端完成签名，避免反复输入口令。

**Agent Forwarding**　把 agent 的签名能力转发到远端主机，方便连续跳转，但有被滥用的风险。

**ProxyJump**　先连跳板机再连目标的连接方式，第二段认证由本机完成。

**端口转发**　把某个 TCP 端口上的流量通过 SSH 通道转送到另一端，分本地、远程、动态三种。

**SOCKS**　一种代理协议，客户端在运行时指定目标地址，常用于动态转发。

**TCP**　传输层的可靠字节流协议，靠序号、确认、重传保证不丢不乱，代价是握手、状态与拥塞控制。

**UDP**　传输层的无连接协议，头部只有 8 字节，不保证送达与顺序，可靠性由应用自己补，适合 DNS、音视频与 VPN。

**QUIC**　跑在 UDP 之上的可靠传输协议，HTTP/3 的底座，把每条流分开重传，避免 TCP 的队头阻塞。

**VPN**　虚拟专用网（Virtual Private Network），在本机与远端网络之间建一条加密隧道，并把整台机器发往内网网段的流量都改从隧道走，使本机在逻辑上成为那个内网的一台机器。与 SSH 端口转发的区别在于它改的是全局路由，程序无感。

**隧道**　把一种协议的包整体装进另一种协议的包里传输，两端各拆一次，是 VPN 与端口转发共用的基本手法。

**封装**　在原始数据外面再加一层头部的过程。封装会占用字节，使可用的 MTU 变小。

**虚拟网卡**　由软件模拟出来的网络接口，没有物理形态。VPN 用它给本机在内网里安一个身份。

**路由表**　记录“发往哪个网段、从哪块网卡出去”的表，决定一个包走本地还是走隧道。

**全隧道**　把默认路由指向隧道的配置方式，所有流量都绕行远端出口，审计完整但速度受限。

**拆分隧道**　只把内网网段放进隧道、其余流量走本地网络的配置方式，速度快但审计有缺口。

**IPsec**　网络层的一组安全协议，用 IKE 协商密钥，用 ESP 封装与加密数据，常见于站点到站点互联。

**IKE**　IPsec 的密钥协商协议，负责在两端之间建立安全关联。

**SSL VPN**　跑在 TLS 之上的 VPN，常用 443 端口，因为和 HTTPS 同端口，穿透性最好。

**OpenVPN**　基于 TLS 的开源 VPN 实现，默认使用 UDP 1194。

**WireGuard**　新一代 VPN 实现，算法组合固定，配置只有几十行，2019 年后进入 Linux 内核。

**802.1X**　链路层的端口准入认证。客户端是申请者，交换机是认证者，RADIUS 服务器做判断，通过后才放行端口。

**EAP**　可扩展认证协议，802.1X 中客户端与认证服务器之间跑的认证框架，密码、证书、令牌都能装进去。

**EAPoL**　EAP over LAN，客户端与交换机之间承载 EAP 的链路层帧，端口未授权时只放行它。

**RADIUS**　集中式认证、授权、计费协议，接收交换机的查询并返回放行或拒绝。

**Portal 认证**　先拿到 IP、再通过网页登录换取放行的认证方式，常见于校园网与酒店网络。

**准入控制**　决定“谁可以接入这张网”的一类机制的总称，802.1X 与 Portal 都属于它。

**iNode**　H3C 的接入客户端，把 802.1X、Portal 与 VPN 拨号装在一个程序里，常见于高校校园网。

**shell**　夹在用户与内核之间的命令解释器，负责拆词、展开、连接与执行。`bash`、`zsh`、`sh` 都是它的实现，登录用哪一个写在 `/etc/passwd` 里。

**内核**　操作系统中直接管理进程、内存、文件系统与网络的部分，只接受系统调用，不接受命令行。

**内建命令**　由 shell 自己执行的命令，如 `cd`、`export`、`exit`，不需要另起进程，因为要改的是 shell 自己的状态。

**伪终端**　用一对虚拟设备模拟终端，master 端由 sshd 持有，slave 端交给 shell。

**会话密钥**　一次连接临时协商出来的对称密钥，用完即弃，泄露了也影响不到别的会话。

**对称加密**　加密与解密使用同一把密钥，速度快，用于加密实际数据。

**非对称加密**　使用公钥与私钥一对密钥，速度慢，用于密钥交换与签名。

**AES**　最常见的对称加密算法，分组长度 128 位，密钥长度 128、192 或 256 位。

**ChaCha20**　流密码，在没有 AES 硬件加速的设备上性能更好。

**GCM**　一种认证加密模式，同时提供加密与完整性校验。

**哈希**　把任意长度输入压成固定长度输出的函数，不可逆，用于比对与指纹。

**SHA-256**　输出 256 位的哈希函数，SSH 与对象存储签名中广泛使用。

**HMAC**　带密钥的哈希，用于验证消息完整性，只有持有密钥的人能算出正确值。

**Diffie-Hellman**　一种密钥交换协议，双方各自算出相同的共享密钥，而共享密钥从不在网络上传输。

**ECDH**　基于椭圆曲线的 Diffie-Hellman，密钥更短，计算更快。

**Curve25519**　一条适合密钥交换的椭圆曲线，对应 SSH 算法 `curve25519-sha256`。

**Ed25519**　基于 Curve25519 的签名算法，密钥 32 字节，签名 64 字节。

**RSA**　基于大整数分解困难性的算法，可用于加密与签名，密钥通常 2048 位以上。

**前向保密**　长期密钥泄露后，过去的会话仍然无法解密，前提是使用了临时密钥交换。

**重密钥**　在连接使用一段时间或传输一定数据后重新协商密钥，不影响上层会话。

**会话标识**　第一次密钥交换产生的哈希，整条连接内不变，用于绑定签名与重密钥。

**KEXINIT**　算法协商消息，双方各发一次，列出各自支持的算法清单。

**ETM**　Encrypt-then-MAC，先认证再解密的数据包处理顺序，OpenSSH 默认使用。

**通道**　SSH 连接内的逻辑数据流，一条连接可同时承载多个通道。

**全局请求**　独立于通道的请求，如请求服务端监听端口（远程转发）。

**堡垒机**　集中管控运维访问的设备，提供统一认证、授权、账号托管与操作审计。

**4A**　认证、授权、账号、审计四个能力的合称。

**JumpServer**　开源堡垒机，组件包括 Core、Luna、Koko、Lion、Magnus、Razor、Chen。

**Koko**　JumpServer 的字符协议网关，处理 SSH、SFTP、Telnet。

**系统用户**　JumpServer 中用于连接资产的凭据模板，包含用户名、认证方式、密码或私钥。

**资产授权**　把用户、资产、系统用户、动作绑定在一起的记录。

**三合一用户名**　网关模式下 `用户@系统用户@资产地址` 形式的登录名。

**会话录像**　记录终端原始字节流与时间戳的文件，可回放当时的屏幕内容。

**Remote-SSH**　VS Code 扩展，通过系统 ssh 客户端连接远端并在远端运行 `vscode-server`。

**vscode-server**　VS Code 在远端运行的服务，提供扩展宿主、文件服务、终端服务。

**对象存储**　以 HTTP 接口存取整个对象的存储服务，无目录树，容量近乎无限。

**桶**　对象的容器，名字全局唯一，访问时用于拼域名。

**键**　对象的名字，可含斜杠，但不表示目录层次。

**ETag**　对象的标识，单文件上传时等于内容 MD5，分片上传时是分片 MD5 的组合。

**分片上传**　把大文件切成多片分别上传，最后合并，支持并发与断点续传。

**预签名 URL**　把签名放进查询参数的临时访问链接，在有效期内可用。

**SigV4**　AWS 的签名算法第四版，被多数对象存储兼容，核心是规范化请求加四层 HMAC。

**规范化请求**　把方法、路径、查询串、头部按固定规则整理成标准形式，是签名的输入。

**访问密钥**　对象存储的凭据，由公开的 ID 与保密的 Key 组成。

**临时密钥**　由安全令牌服务签发的短期凭据，带有效期与会话令牌。

**生命周期规则**　按时间自动转换存储类型或删除对象的规则。

**纠删码**　把数据编码成多份分片分散存放，坏掉若干份仍可恢复，用于提升持久性。
