# 进程会死，服务要活

> 在 SSH 窗口里跑起来的程序，属于那个窗口，不属于这台机器。

## 11.1 关掉窗口，网站就没了

这一章说的都是服务器上的事，命令也在服务器的终端里敲。你本地电脑上那个窗口只是终端，真正跑程序的是另一头。

这件事几乎每个人都会遇到一次。

你登录服务器，进入项目目录，敲下 `python app.py`。终端里出现启动日志，你在浏览器里打开网站，很好，能用。

你关掉终端，去吃了顿饭。回来再打开网站，打不开。

你重新登录，发现程序不见了。你以为它崩了，于是重新跑一遍，又好了。然后在某个时刻它又消失，反复几次之后你开始怀疑服务器不稳定。

服务器很稳定。问题在于你怎么启动这个程序。

## 11.2 为什么它会跟着窗口一起死

你 `ssh` 进来的时候，服务器上的 sshd 会给你开一个会话，在会话里起一个 shell，你在这个 shell 里敲命令。你跑的程序是这个 shell 的子进程。

你关掉窗口，连接断开，sshd 会结束这个会话。结束的方式是给会话里的进程发一个信号，叫 SIGHUP，意思是挂断。默认情况下，收到这个信号的程序会退出。

所以它不是崩了，是被关了。这是一种设计，因为在终端里跑的东西本来就该跟着终端走。

理解了这一点，后面所有方案都是在解决同一个问题，怎么让程序脱离这个会话。

## 11.3 创可贴：nohup

最老的办法。

```bash
nohup python app.py > app.log 2>&1 &
```

`nohup` 的意思是忽略挂断信号。`>` 把输出写进文件。`2>&1` 把错误输出也并进去。末尾的 `&` 让它到后台跑。

这样关掉窗口它就不会死了，日志也在 `app.log` 里。

够用，但只够用一小会儿。它有三个明显的缺陷。

服务器重启，它不会自己起来。程序因为某个异常退出，它不会被拉起。日志文件会一直长，几个月后能把磁盘写满。

你可以在网上找到一堆脚本解决这三个问题，那些脚本本质上都在重新发明同一个东西。那个东西叫服务管理器。

## 11.4 正解：systemd

现在的 Linux 发行版都自带 systemd，它的工作就是管这些长期运行的进程。你写一个描述文件，告诉它怎么启动你的程序，剩下的它管。

在 `/etc/systemd/system/` 下建一个文件，比如 `myapp.service`。

```ini
[Unit]
Description=My App
After=network.target

[Service]
User=app
WorkingDirectory=/srv/myapp
EnvironmentFile=/srv/myapp/.env
ExecStart=/srv/myapp/.venv/bin/uvicorn app:api --host 127.0.0.1 --port 8000
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

逐行看。

`User=app` 指的是用哪个用户跑。不要用 root，除非你确实需要。用一个普通用户，即使程序被攻破，攻击者拿到的也只是这个用户的权限。

`WorkingDirectory` 是工作目录。程序里写的相对路径都相对于它。

`EnvironmentFile` 是环境变量的文件，第十四章会讲。密钥放这里，不要写在代码里。

`ExecStart` 是启动命令。注意端口绑的是 `127.0.0.1`，因为外面有 nginx，这是第三章那条规矩。

`Restart=always` 是关键。程序不管因为什么退出，三秒后自动拉起。

`WantedBy=multi-user.target` 决定它开机自启。

写好之后。

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now myapp
sudo systemctl status myapp
```

`enable` 是开机自启，`--now` 是顺便现在就启动。

之后你的日常操作就三条。

```bash
sudo systemctl restart myapp
sudo systemctl status myapp
journalctl -u myapp -f
```

改了代码要重启，看它活着没有用 status，看日志用 journalctl。日志它会自己管，不会把磁盘写满。

## 11.5 那 Docker 是什么

你会看到另一种做法，把程序打包成镜像，用 Docker 跑。

```bash
docker run -d --restart always -p 127.0.0.1:8000:8000 myapp
```

Docker 解决的是另一个问题，环境一致性。它把程序需要的系统库、Python 版本、依赖全都打包在一起，换一台机器跑起来效果一样。

它不解决“进程要活着”这个问题，`--restart always` 才是干这个的，那本质上还是让 Docker 这个服务去管你的容器。

用不用 Docker 取决于项目复杂度。一个 Python 脚本不需要，一个要装一堆系统依赖的服务值得。判断标准是，你有没有遇到过“在我电脑上能跑”这句话。

## 11.6 一个自查习惯

部署完之后，关掉 SSH 窗口，等一分钟，再打开网站。

如果打不开，说明它还在跟着会话走。这个测试比看任何配置都快。
