# 把文件送到远方

> 传大文件之前，先想清楚断了怎么办。

## 15.1 传到百分之九十

你在本地有个三个 G 的数据集，要传到服务器上。网上搜了一下，`scp` 最简单。

```bash
scp dataset.tar.gz alice@203.0.113.24:/home/alice/
```

传了四十分钟，进度到百分之九十，网络抖了一下，连接断了。

终端回到提示符，服务器上留了一个不完整的文件，你也不知道它不完整。重新来一遍，又是四十分钟，心里一直悬着。

这件事有一个更稳的做法。

## 15.2 scp 是什么

`scp` 和下面的 `rsync` 都在你自己的电脑上敲。它们做的事是把本地的东西送到服务器，或者反过来，所以起点是你的电脑，不是服务器。

`scp` 是 secure copy，走的就是 SSH 那条加密通道，用法跟 `cp` 很像。

```bash
scp 本地文件 alice@主机:/远端路径      # 上传
scp alice@主机:/远端文件 ./            # 下载
scp -r ./mydir alice@主机:/home/alice/ # 整个目录
scp -P 2222 file alice@主机:/tmp/      # 注意端口是大写 P
```

它的优点是简单，几乎所有机器都有。缺点是它没有断点续传，断了就得从头再来。传小文件完全够用，传几百兆以上就该换工具。

## 15.3 rsync 为什么更好

```bash
rsync -avz --progress dataset/ alice@203.0.113.24:/home/alice/dataset/
```

`-a` 保留权限和时间戳，`-v` 显示过程，`-z` 传输时压缩，`--progress` 显示进度。

它有三个 scp 没有的能力。

第一，只传变化的文件。第二次同步时，没变的东西它不传。这个特性在反复部署时非常省时间。

第二，断点续传。加 `--partial`，断了之后重跑同一条命令，它接着传。

第三，可以排除。`--exclude "*.log"` 跳过日志，`--exclude ".git"` 跳过版本库。传项目目录的时候特别有用。

有一个细节要注意，源路径末尾有没有斜杠含义不同。`dataset/` 是把里面的内容传过去，`dataset` 是把整个目录传过去，会多一层。这个坑很经典，传完发现路径多了一层目录，就是它。

## 15.4 传大文件的三件事

**先打包压缩。** 一堆小文件直接传很慢，因为每个文件都有开销。先 `tar -czf` 打成一个包，传输效率差好几倍。

**传完校验。** 网络传输理论上不会出错，实际上偶发的截断和损坏是有的。传完在两边各算一次哈希。

```bash
sha256sum dataset.tar.gz
```

两个值一模一样才算成功。这一步花几秒钟，能避免你花两小时排查“为什么解压失败”。

**想清楚断了怎么办。** 这就是 rsync 存在的理由。如果文件大到几个 G，还可以考虑分片传，每片几百兆，断了只重传一片。

## 15.5 不想用命令的话

图形工具也行，WinSCP、FileZilla、Cyberduck 都支持 SFTP。它们底层走的还是 SSH，只是给你一个两栏的文件管理器界面，可以拖拽。

拖拽的缺点是它不告诉你发生了什么，出错了只给一个红叉。传重要的东西，还是建议用命令行，至少能看到错在哪。

VS Code 也有远程文件浏览，第二十章会讲。它的优势和编辑器结合在一起，改配置文件很顺手，但传几百兆的数据不合适。

## 15.6 一个安全提醒

用 `scp` 或者 `rsync` 的时候，你的私钥在本地，数据在加密通道里，这是安全的。

但不要把私钥本身传到服务器上。有些人为了让服务器能连另一台机器，把自己的私钥 `scp` 上去，这是把钥匙副本放在了别人家里。正确做法是在服务器上单独生成一对新的密钥。

也不要为了方便，把文件传到 `/tmp` 然后忘了删。`/tmp` 是所有用户都能读的地方。

> **这一章记住一句**
>
> 小文件 scp，大文件 rsync，传完一定校验。
