# 怎么向 AI 描述你的环境

> 你给的信息，决定了它给的是答案还是猜测。

## 21.1 一场无效的对话

你：网站打不开了，怎么办。

AI：可能是端口没开，也可能是防火墙，还可能是 DNS 解析问题。你可以先检查一下……

你按它说的试了五个方向，两个小时过去了，还没好。

这场对话的问题不在 AI。它手里什么信息都没有，只能把常见原因列一遍。这就像一个医生问你哪里不舒服，你说“我不舒服”，他只能从感冒查到心脏病。

## 21.2 它看不见你的机器

AI 没有你的屏幕，没有你的终端，不知道你在哪台机器上，不知道你的系统版本，不知道你敲过什么命令，也不知道完整的报错。

它所有判断都建立在你打的字上。你打的字少，它就只能猜。猜出来的东西听起来都很合理，因为那些确实是最常见的原因。

所以有效提问的关键不是措辞礼貌，是把现场搬过去。

## 21.3 一份病历

按这六项说，一次就能省掉十轮来回。

**一，你在哪台机器上。** 本地 Mac 还是云服务器，Ubuntu 22 还是 CentOS 7。很多问题的答案跟系统强相关。

**二，你想做什么。** 一句话说清目标，比如“让外网能访问部署在服务器 8000 端口的接口”。

**三，你做了什么。** 完整的命令，不要概括。把 `sudo systemctl start myapp` 写成“我启动了服务”，信息就丢了。

**四，发生了什么。** 完整的报错，从第一行到最后一行。堆栈的第一行告诉你是什么错，最后一行告诉你错在哪一行代码，中间那几十行很多时候可以省略，但两头不能少。

**五，你已经试过什么。** 这一条最省时间，避免它让你重复你已经做过的动作。

**六，你的网络位置。** 在家里还是公司，有没有 VPN，是不是通过跳板机。同一个问题在这三种环境下的原因完全不同。

一个实际的例子。

```text
环境：腾讯云 Ubuntu 22.04，公网 IP 203.0.113.24，我在家里直连，没有 VPN。
目标：让外网访问 myapp，它监听 127.0.0.1:8000，前面用 nginx 转 443。
做了：systemctl start myapp，nginx -t 通过，systemctl reload nginx。
现象：浏览器访问 https://myapp.com 返回 502，nginx 的 error.log 里有一行
      connect() failed (111: Connection refused) while connecting to upstream。
试过：重启 myapp，确认 status 是 active，安全组已放行 443。
```

这段话里有足够的信息让任何懂行的人三十秒内定位，问题在后端监听的是 `127.0.0.1` 还是端口对不对，而 nginx 的报错已经明说了连不上 upstream。

## 21.4 三个能让回答变好的习惯

**让它先诊断，别急着改。** 加一句“先列出可能的原因，按可能性排序，先不要改代码”。它会给你一个清单，你挑一个去验证。比它直接给你一段新代码要可靠得多。

**一次只改一件事。** 同时改三个配置，好了你也不知道是哪个起的作用，坏了更不知道是哪一步坏的。改一个，验证，再改下一个。

**要它给验证方法。** 不只是“改成这样就好了”，而是“改完之后运行这条命令，如果输出是这样就说明成功了”。有了验证方法，你才能确认它到底有没有说对。

## 21.5 有些话不能照抄

AI 给的建议里，有一批是“能解决问题但代价很大”的。它们出现在训练数据里，因为它们在教程里很常见，教程假设你在一个可以随便折腾的沙盒里。

| 它可能会说 | 为什么危险 |
| --- | --- |
| `chmod 777` | 把文件权限对所有人打开，等于拆锁 |
| `0.0.0.0` 绑定数据库 | 数据库直接暴露在公网，几小时内就会被扫到 |
| 关闭防火墙 | 一句 `systemctl stop firewalld` 能解决很多问题，也会带来很多问题 |
| `curl xxx \| sudo bash` | 用一个陌生脚本以管理员身份执行 |
| `rm -rf` 加变量 | 变量是空的时候，它会删掉你不想删的东西 |
| 把密钥写进代码 | 一旦提交就泄露 |
| 直接改 `sshd_config` 然后重启 | 改错了就再也登不进去 |
| `--privileged` 跑容器 | 容器里的程序拿到了宿主机的权限 |

遇到这些，问一句“有没有更安全的做法，只开放需要的那一部分”。大部分时候有。

## 21.6 一个反向的用法

你也可以让 AI 帮你检查。

把当前的配置贴给它，问“这里面有没有安全隐患”。或者把你的排查思路讲一遍，问“这个顺序有没有问题”。

它很擅长做这种审查，因为这类知识在它的训练数据里非常密集，而且不依赖于它能否连上你的机器。
