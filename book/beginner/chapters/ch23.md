# 安全和花钱的底线

> 这两件事的共同点是，出问题的时候都很突然。

## 23.1 十条规矩

**一，数据库和缓存不绑 `0.0.0.0`。** 第三章那个故事不是编的，扫描器二十四小时在工作，一个开放端口的 Redis 平均几小时内就会被找到。

**二，密钥不进 git。** 第十四章。泄露了先作废，别先删文件。

**三，不用 root 跑业务。** 建一个普通用户，用 systemd 的 `User=` 指定。攻击者拿到的权限就是那个用户的权限。

**四，关掉密码登录。** 密钥配好之后，`PasswordAuthentication no`。服务器每天被尝试几万次密码，关掉能省很多事。

**五，能限定来源就限定。** 安全组的来源写自己的 IP，管理后台加一层 Basic Auth，SSH 端口只对公司出口 IP 开放。

**六，定期打快照。** 大改动之前打一个。这是唯一能救回“我删错了”的东西。

**七，备份要异地。** 同一台机器上的备份，机器挂了就一起没了。至少放一份在对象存储或者另一台机器上。

**八，最小权限。** 一个程序只需要读一个桶，就别给它整个账号的权限。出事的时候，损失范围就是权限范围。

**九，看到 `777` 和 `curl | bash` 停一下。** 这两样在教程里很常见，在事故报告里也很常见。

**十，日志要留。** 出事之后最想知道的是“它是怎么进来的”。日志能回答，没有日志就只能猜。

## 23.2 四个烧钱的坑

云服务的账单有一种特点，它不会在某一天突然翻十倍，它会在你忘记的某个地方慢慢涨，直到你某天点开账单。

**按量计费的机器忘了关。** GPU 机器一小时几十块，睡一觉就是几百。用完当场销毁，不要只关机。

**带宽和流量。** 按流量计费的机器，被人刷一次可能就是一晚上几百 G。前面加 CDN 或者设个告警。

**对象存储的请求费。** 存储本身很便宜，请求次数按万次计费。程序里一个小循环疯狂列目录，或者日志级别开成 debug 往对象存储写，账单会很难看。

**快照和镜像堆积。** 每次打快照都占空间，自动快照策略如果没设保留数量，一年下来能存几十份。

设一个账单告警，花五分钟，能救命。大部分云平台都有这个功能，阈值设成你月均消费的两倍。

## 23.3 备份的三二一

行业里有一句老话，三个副本，两种介质，一份异地。

对个人项目可以简化成两条。至少两个地方，至少一个是自动的。

手动备份的问题是你会忘记。配一个定时任务，每天把数据库导出一份传到对象存储，比任何自觉都可靠。

还有一个常被忽略的点，备份要能恢复才算备份。每隔一段时间真的去恢复一次，你会发现很多备份其实是坏的，或者缺了某个关键文件。

## 23.4 一个判断标准

遇到“要不要开这个端口”“要不要给这个权限”“要不要关这个检查”的时候，用一个问题来判断。

最坏的情况发生时，我能承受吗。

数据库被拖走，能承受吗。服务器被拿去挖矿，账单来了能承受吗。代码泄露，能承受吗。

承受不了的事，就不要为了省五分钟去冒险。能承受的事，就别过度设计，那也是一种浪费。

> **这一章记住一句**
>
> 安全和成本都不是配置问题，是习惯问题。
