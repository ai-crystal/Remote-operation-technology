# 密码不能住在代码里

> 密钥一旦进了 git，就当它已经公开了。

## 14.1 一个昂贵的疏忽

有人在本地写了个小工具，把云存储的密钥直接写在 `config.py` 里。跑通了，很开心，顺手 `git add .`，推到 GitHub。

仓库是公开的，因为他想给别人看这个工具。

两天后他收到云厂商的短信，说账户余额不足。登录一看，对象存储的请求量是平时的几千倍，有人在用他的密钥跑业务。

从推送到被用，中间隔了十几分钟。扫描 GitHub 找密钥的机器人是二十四小时不休息的。

## 14.2 环境变量是什么

环境变量是操作系统给每个进程准备的一包键值对。程序启动的时候继承下来，运行的时候随时能读。下面这些都在服务器上，也就是程序真正运行的那台机器。

```bash
export DATABASE_URL="postgres://user:pass@127.0.0.1:5432/mydb"
python app.py
```

这样 `app.py` 里可以用 `os.environ["DATABASE_URL"]` 读到它，而代码文件里一个字都没有。

好处有三个。代码可以公开分享，密钥不在里面。不同环境可以用不同的值，同一份代码在本地连本地库，在服务器连服务器库。改密钥不用改代码，重启一下就行。

## 14.3 放在哪个文件里

最常用的做法是项目根目录下一个 `.env` 文件。

```text
DATABASE_URL=postgres://user:pass@127.0.0.1:5432/mydb
COS_SECRET_ID=AKIDxxxxxxxx
COS_SECRET_KEY=xxxxxxxx
```

Python 里用 `python-dotenv` 读进来，或者第十一章 systemd 那个 `EnvironmentFile=` 直接读。

关键是这个文件不能进 git。

```text
# .gitignore
.env
*.pem
*.key
```

很多人是在 `git add .` 之后才想起来加，那时候已经晚了，文件已经进了历史。加 `.gitignore` 只能防止以后，不能擦掉过去。

所以还有一个习惯，提交之前先跑一次 `git status`，看看有没有不该出现的文件。这件事花三秒钟，能省掉一次密钥轮换。

为了别人 clone 下来知道要配哪些变量，可以提交一个 `.env.example`，里面只有键名，值是空的或者假值。

## 14.4 已经泄露了怎么办

这是这一章最重要的一段。

第一件事是把旧密钥作废，去云平台的控制台禁用它，或者直接删掉。不要先改代码，不要先删 commit，先去作废。因为从泄露到滥用可能只有几分钟，而你清理 git 历史要花半小时。

第二件事是生成新的密钥，更新到服务器和本地，确认服务正常。

第三件事是看日志，查这段时间有没有人用过这个密钥。对象存储的访问日志里能看到请求来源和操作，如果有陌生的 IP 在拉数据，那就要考虑数据已经泄露出去了。

删 commit 有用吗。几乎没用。git 的历史是分布式的，你的本地删了，GitHub 上的对象还在，别人的 fork 和 clone 里也还在。除非你重写历史并强制推送，而且假设没有别人克隆过，才有一点意义。即使那样，机器人早就抓走了。

所以顺序永远是，作废、换新、查日志。删代码是最后一步，而且主要是为了以后不再犯。

## 14.5 权限给到刚好

密钥泄露的损失有多大，取决于这把钥匙能开几扇门。

如果它是一把主账号的密钥，权限是全部，那攻击者能做任何事，包括开机器、删数据、改配置。

正确做法是给每个用途建一个子账号，只给它需要的权限。

举个例子。你的程序只需要往一个桶里读写文件，那就建一个子账号，只授权这个桶的读写，别的什么都不给。这样即使泄露，损失范围也就是这个桶。

更进一步，可以用临时凭证。程序启动时用一个长期密钥换一组几小时后过期的临时密钥，之后都用临时的。即使泄露，过一会儿就失效了。

还有一种做法是限制来源 IP。密钥只能从你服务器的 IP 使用，从别的地方用会失败。这一条对固定 IP 的服务器很有效。

## 14.6 不要相信“我删掉了”

有几个地方容易留下痕迹。

笔记本里的 `.ipynb` 文件。Jupyter 会把变量值存进输出里，你 `print` 过一次密钥，它就躺在里面了。

终端的历史记录。`~/.bash_history` 里可能有你 `export` 过的密钥。

截图和录屏。分享调试过程的时候，密钥经常就在屏幕上。

日志。程序报错时如果把整个配置打出来，密钥就进了日志文件。

部署脚本和 CI 配置。写死在 `.github/workflows` 里的密钥是另一个高频事故点。

这件事没有一劳永逸的办法，只能养成一个反射，看到 `AK`、`sk-`、`SECRET`、`TOKEN` 这类字样的字符串出现在不该出现的地方，就停下来。

> **这一章记住一句**
>
> 密钥写进代码，等于写在公告栏上。泄露了先作废，别先删文件。

第三篇到这里结束。程序能跑、能对外、能保密。第四篇换个话题，数据放在哪。
