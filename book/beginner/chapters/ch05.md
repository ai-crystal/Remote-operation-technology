# 挂号信和传单

> 连不上和连上了没反应，是两种完全不同的病。

## 5.1 两个让人抓狂的现象

第一个。你敲下 `ssh`，光标停在那里，二十秒、三十秒，什么也不显示。最后跳出一行 `Connection timed out`。

第二个。网页打开了，标题出来了，然后一直转圈，白屏，一分钟之后浏览器说“响应超时”。

这两件事看起来都是“卡住了”，修起来完全不是一回事。要理解为什么，得知道数据在路上是怎么走的。

## 5.2 包裹会丢

数据在网线上不是一整块流过去的，它被切成很多小块，每块加上一个头，写明从哪来、到哪去、是第几块。这叫数据包。

包在途中会经过十几个路由器，每个路由器都在做同一件事，看一眼目的地，往前送一格。这个过程没有总指挥，也没有人保证它一定送到。线路拥堵、设备故障、路由抖动，包就可能丢掉。

所以网络传输的本质不是“送过去”，而是“尽量送过去，并且想办法知道有没有送到”。

对付这件事有两套办法，一套叫 TCP，一套叫 UDP。

## 5.3 TCP 像挂号信

寄挂号信的时候，邮局会给你一张回执。对方签收了，你才知道送到了。没签收，你会去查。

TCP 干的就是这件事，而且做得更细。它在正式发数据之前，先跟对面确认三件事。我能发吗，你能收吗，我们都说同一种话吗。

这个过程就是三次握手。用大白话说。

```text
你：在吗，我想跟你说话。
对方：在，你说。你也在吗？
你：在。开始吧。
```

三次是为了确认双方都能发也能收。两次不够，因为对方不知道自己那句话你有没有收到。

握手成功之后，连接就建立了。之后每个包都有编号，收方按编号拼回去，丢了的重发，乱序的排好。发完一批要等确认，确认没来就重发。这套机制的代价是慢一点，好处是只要连接没断，你收到的数据就是完整的、按顺序的。

网页、SSH、数据库、传文件，全是 TCP。你几乎所有的“正经事”都跑在它上面。

## 5.4 UDP 像发传单

UDP 不管这些。它把数据装好，写上地址，扔出去，然后就不管了。丢了吗，可能。顺序乱了吗，可能。对方收到了吗，它不知道，也不问。

听起来很糟糕，但它有个巨大的优点，快。不用握手，不用等确认，不用重发，发出去就完事。

视频通话、在线游戏、直播，用的都是 UDP。丢一两帧没关系，画面糊一下，下一秒就补上了。要是用 TCP，丢一个包就得停下来等重发，画面会卡成幻灯片，那才是真的不能忍。

DNS 查询也用 UDP，因为一次问答就结束了，为这一句话建立连接太浪费。

| | TCP | UDP |
| --- | --- | --- |
| 像什么 | 挂号信，有回执 | 发传单，扔了就走 |
| 先握手吗 | 握 | 不握 |
| 丢包怎么办 | 重发 | 不管 |
| 快不快 | 慢一点 | 快 |
| 谁在用 | 网页、SSH、数据库 | 视频、游戏、DNS |

## 5.5 于是就有了两种卡住

回到开头那两个现象。

第一种，`ssh` 一直卡到超时。这说明三次握手就没成功，你的“在吗”没得到回应。可能是包根本没到，也可能到了但被防火墙丢了，对面连一个字都没回。这种情况的典型表现是等很久，然后报超时。

第二种，网页白屏转圈。这时候三次握手是成功的，连接建立起来了，你的请求也发出去了，但对面迟迟不回话。可能是程序卡在查数据库，可能是在等一个外部接口，也可能它压根没实现这个路由。连接是好的，是人不说话。

这两件事的排查方向完全不同。前者去查网络和防火墙，后者去查程序日志。分不清这两者的人，会在错误的地方浪费大量时间。

## 5.6 一个常见的误会

`ping` 通，说明什么。

说明你的包能到那台机器，它也能回你。仅此而已。

`ping` 用的不是 TCP，是另一套叫 ICMP 的协议。很多防火墙的默认策略是“允许 ping，但拒绝其他端口”。所以你 ping 得通，二十二号端口照样连不上，这两件事不矛盾。

反过来说，ping 不通也不一定代表机器死了。有些服务器直接在防火墙上禁掉了 ICMP，就是为了不让人扫。它活着，只是不回应这种招呼。

判断一个端口通不通，要用能发起 TCP 连接的工具。下面这两条都在你自己的电脑上敲，测的是从你这儿到那边的路，不是服务器自己连自己。

```bash
nc -vz 203.0.113.24 22
```

或者更直接一点。

```bash
curl -v telnet://203.0.113.24:22
```

Windows 上可以用 `Test-NetConnection 203.0.113.24 -Port 22`。这类工具做的事就是替你握手一次，成不成马上告诉你，不用等二十秒。
