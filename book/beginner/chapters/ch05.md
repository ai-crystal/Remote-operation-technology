# 登录成功之后，服务器上发生了什么

## 5.1 那个提示符背后，站着两个程序

你在本地敲 `ssh`，这个程序跑在你自己的电脑上，负责发起连接、加密、把你的按键送出去。

服务器那边，有一个叫 `sshd` 的程序，一直守在 22 端口上等别人来连。它才是接待你的那个人。

验证通过之后，`sshd` 并不直接把机器交给你。它做三件事：准备一个“终端”，把你的输入输出接上去；复制出一个新进程，换成你的身份；在那个进程里启动你的 **shell**。

于是你看到的那个提示符，是 shell 打印的。

## 5.2 shell 是什么

shell 是“外壳”的意思。操作系统里面那层管硬件和进程的部分叫内核，外面这层负责把人话翻译成内核能懂的动作，就是 shell。

它做的事情很朴素：打印提示符、读你敲的一行、解释成一个动作、执行、把结果送回来。

“解释”包括几件活：把一行拆成命令和参数、把 `*.log` 展开成一串文件名、把 `>` 理解成“把输出写进文件”、判断这条命令是自己就能做（比如 `cd`）还是要另起一个程序。

常见的 shell 有 `bash`、`zsh`、`sh`。Linux 服务器上默认多半是 `bash`。

## 5.3 一条命令，一个进程

你敲 `ls`，shell 并不是“自己变成了 ls”，而是**复制**出一个小进程，让它去执行 `ls`，自己在一旁等。执行完，shell 拿回结果，重新显示提示符。

这个“复制出子进程”的动作叫 fork。所以：

- 你登录时，`sshd` fork 出 shell
- 你敲一条命令，shell fork 出那个命令
- 那个命令要是再启动别的程序，还会继续往下 fork

用 `ps -ef` 能看到这棵树：`sshd` 下面挂着 `sshd`，再下面是 `bash`，再下面是你正在跑的程序。

有一条规则值得记住：有些命令必须由 shell 自己做，比如 `cd`、`export`。因为它们改的是 shell 自己的状态（当前目录、环境变量），交给子进程改，子进程一退出就白改了。

## 5.4 权限：为什么有些文件你动不了

Linux 里每个文件都记着三组权限：属主、属组、其他人，每组三位，分别是读、写、执行。

`ls -l` 输出的第一列就是它：

```text
-rw-r--r--  1 alice dev  1204 Nov  4 10:12 notes.txt
drwxr-x---  2 alice dev  4096 Nov  4 10:12 project
```

第一行表示：属主可读写，属组可读，其他人可读。换成数字是 644。

第二行是目录，属主可读写执行，属组可读执行，其他人什么都没有，数字是 750。

目录上的“执行”位含义特殊，它表示“能不能进入这个目录”。没有它，里面的文件权限再大，你也碰不到。

这件事和 SSH 有一个硬性交集：**私钥文件的权限必须是 600**。太松的话，`ssh` 会拒绝使用它，因为它怕别人也能读到你的钥匙。

## 5.5 路径和环境变量：命令为什么找得到

你敲 `python3`，shell 并不知道它在哪里，它按一个叫 `PATH` 的清单，逐个目录去找。

`PATH` 是一串用冒号分隔的目录。`echo $PATH` 能看到它。你自己装的工具，如果不在这些目录里，就会提示“命令找不到”。

登录时，shell 会读几个文件来设置 `PATH` 和其他变量。读哪几个，取决于它是“登录 shell”还是“交互式 shell”——这也是为什么你在 `.bashrc` 里加的配置，有时候 `ssh` 登录后不生效。

## 5.6 这一章的三句话

- 你看到的提示符是 shell 打印的，它跑在 `sshd` 为你会话启动的进程里。
- 每敲一条命令，shell 就复制一个子进程去执行；改 shell 自己状态的命令除外。
- 权限决定你能不能碰文件，`PATH` 决定命令找不找得到，私钥必须是 600。
