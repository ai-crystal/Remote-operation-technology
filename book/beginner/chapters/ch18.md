# 挖一条地道

> 隧道不是穿墙，是把管子插在已经开着的门里。

## 18.1 一台看不见的机器

公司的测试环境里有一台机器，地址是 `10.0.0.9`。上面跑了一个管理后台，只能在公司内网打开。

你在家，想连上去看看。

直接 `ping 10.0.0.9` 是不通的，因为这个地址只在公司内网有意义，就像你邻居家的门牌号，在你家小区之外没人认。

但你有另一台机器的访问权限，公司的跳板机 `jump.example.com`，它有公网地址，你能 SSH 上去。跳板机同时连着内网，它两个世界都够得着。

问题是，你登录到跳板机之后，只能在它上面敲命令。你想用浏览器打开 `10.0.0.9` 的管理后台，浏览器在你自己的电脑上，它够不着。

## 18.2 SSH 隧道这个想法

SSH 的连接本身是一条加密通道，从你的电脑通到跳板机。既然这条管道已经通了，能不能顺手在里面运点别的东西。

能。这就是端口转发，也常被叫做 SSH 隧道。下面这条命令在你自己的电脑上敲，不要在跳板机上敲。

```bash
ssh -L 8080:10.0.0.9:80 alice@jump.example.com
```

`-L` 的意思是本地转发。拆开看这三段。

`8080` 是你自己电脑上要开的端口。

`10.0.0.9:80` 是最终要访问的目标，由跳板机替你去连。

登录之后，这条命令不会给你一个命令提示符，它就停在那里，像个守门人。你打开浏览器，访问 `http://127.0.0.1:8080`，看到的就是 `10.0.0.9` 的管理后台。

![图 18-1　本地转发把远方的端口搬到本机](../images/18/fig18_1.png)

数据的实际路径是这样的。浏览器把请求发给本机的 8080，ssh 客户端接住，塞进加密通道，送到跳板机。跳板机拆开，替你去连 `10.0.0.9:80`，拿到回应，再塞回通道传给你。

对你来说，那个内网服务好像就长在你自己电脑上。

## 18.3 一个默认值和它的风险

`-L 8080:...` 默认只绑 `127.0.0.1`，也就是只有你这台电脑能用。这通常是你要的。

如果写成 `-L 0.0.0.0:8080:...`，同一个办公室的人也能通过你的电脑访问那个内网服务。方便，但等于你开了一个后门，而且所有的访问都会记在你的账号上。

第三章那条规矩在这里同样适用。需要别人用的时候再开，用完就关。

## 18.4 反过来：把家里的东西给外面看

还有一种需求方向相反。

你在自己电脑上跑了一个服务，想让公网上的某台服务器能访问它。比如你在本地调试一个微信回调，微信的服务器要能访问到你的接口。

`-R` 就是干这个的，远程转发。

```bash
ssh -R 9000:127.0.0.1:3000 alice@203.0.113.24
```

意思是，在那台服务器上开一个 9000 端口，所有连到它的请求，通过这条 SSH 通道，转回你本地的 3000。

现在任何人访问 `203.0.113.24:9000`，实际连的是你家的电脑。

这就是内网穿透的基本原理。市面上那些工具，frp、ngrok、cloudflared、Tailscale，做的事情本质相同，只是把这条通道做得更稳、更好配、还顺带解决了域名和证书。

它们解决的是第一章那个问题，家里的电脑没有公网地址，外面的人找不到。`-R` 是一个临时办法，专用工具是长期办法。

一个限制要知道，服务器上的 sshd 默认只允许把这种转发端口绑在 `127.0.0.1`，外面访问不到。要用得改 `GatewayPorts` 配置，或者用那些专门的工具，它们会处理好。

## 18.5 还有两种

`-D` 是把 SSH 当成一个 SOCKS 代理。浏览器配一下，所有流量都从跳板机出去。适合临时需要“从另一个地方上网”的场景。

`-J` 是跳板机连跳板机。

```bash
ssh -J alice@jump1,alice@jump2 alice@10.0.0.9
```

不用先登录第一台再登录第二台，一条命令直达。它的好处是本地不需要为中间那两台配置密钥，认证是在链条上逐段完成的。

## 18.6 别忘了它是什么

隧道很有用，但它做的事实上是绕过网络边界。

公司把数据库放在内网，就是为了不让外面直接连。你挖一条隧道连上去，从技术上讲没有破坏任何东西，从管理上讲是绕过了人家的安全设计。很多公司的安全策略明确禁止这种行为，而且流量审计是能看出来的。

自己家的实验环境随便玩。公司的环境，先问一句能不能。

> **这一章记住一句**
>
> `-L` 把远方搬到本地，`-R` 把本地送到远方。

下一章讲正规军怎么做这件事。公司不会给你开一条隧道，它们有班车和前台。
