# 锁和钥匙

> 公钥可以贴在任何地方，私钥只能待在自己电脑上。

## 9.1 一个下午的报错

你按教程生成了密钥，把公钥贴到服务器上，然后连。

```text
alice@203.0.113.24: Permission denied (publickey).
```

你把公钥又贴了一遍，还是不行。你怀疑复制少了字符，重新复制，还是不行。你在服务器上把 `sshd_config` 翻了一遍，看不出问题。最后发现是权限。`~/.ssh` 目录的权限是 777，sshd 一看就不干了。

这个报错在中文互联网上有几十万条提问，原因通常就三个，公钥没贴对、权限不对、私钥没被用上。理解原理之后，这三个都能自己查。

## 9.2 密码为什么不够

密码的问题有三个。第一，人设的密码太弱，而且到处复用。一个网站泄露，攻击者拿同一套用户名密码去试你的服务器，这叫撞库。

第二，密码可以被暴力猜。服务器放在公网上，每天会有成千上万次登录尝试，这在日志里看得一清二楚。第三，密码在网络传输中需要一个安全的通道，如果通道本身有漏洞，密码就暴露了。密钥对解决的是这三个问题的合体。它不用传输秘密，也不存在弱口令，猜也没法猜。

## 9.3 一把锁和一把钥匙

密钥对是成对生成的两个文件。私钥是钥匙，留在你自己电脑上，谁都不能给。公钥是锁，可以随便发，贴到服务器上、贴到 GitHub 上，都没有风险。

它们的关系是这样的。服务器上存着你的锁，你敲门的时候，服务器拿出一段随机数据，用你的锁锁上，问你，你能打开吗。你用私钥打开，把结果给它，它验证一下，对上了，就让你进。

整个过程里，私钥从来没有离开过你的电脑。服务器拿到的只是一个“你能解开这把锁”的证明。这就是它比密码安全的地方。

顺便说一个很多人记反的地方。公钥是锁，私钥是钥匙。文件后缀 `.pub` 的是公钥，没有后缀的那个是私钥。贴到服务器上的是 `.pub` 那个。

## 9.4 生成和安装

这一节的两条命令都在你自己的电脑上敲。私钥生成在本地，公钥再传上去。

```bash
ssh-keygen -t ed25519 -C "my laptop"
```

它会问你存哪里，默认 `~/.ssh/id_ed25519`，回车就行。名字里的 `ed25519` 不是随机数，是算法的名字。`-t` 后面跟的就是算法，用 `-t rsa` 生成的文件就叫 `id_rsa`。数字 25519 来自它用的那条曲线，曲线建在 2 的 255 次方减 19 这个数上。随机的是生成的密钥内容，名字是固定的。然后问你要不要设一个口令 passphrase，可以设也可以不设。设了更安全，每次用要输一次，有办法免掉（`ssh-agent`，后面提一句）。生成完会得到两个文件。

```text
~/.ssh/id_ed25519       私钥，钥匙，绝对不给别人
~/.ssh/id_ed25519.pub   公钥，锁，可以到处贴
```

安装公钥最省事的办法是 `ssh-copy-id`。

```bash
ssh-copy-id -i ~/.ssh/id_ed25519.pub alice@203.0.113.24
```

它会把公钥追加到服务器上的 `~/.ssh/authorized_keys` 文件末尾。如果服务器上没有这个文件，它会创建。

手动做也行，就是把 `.pub` 文件的全部内容复制粘贴到服务器那个文件里，一行一个公钥。注意是追加，不要覆盖，覆盖了别人的钥匙就进不来了。

## 9.5 权限这件事不是形式主义

下面这几条在服务器上敲，改的是服务器上那个用户的家目录。家目录是每个用户在机器上的私人文件夹，`~` 就是它的简写，而且指的不是一个固定路径，是“你当前登录的那个人”的家目录。以 alice 登录，`~` 是 `/home/alice`；以 root 登录，`~` 是 `/root`。所以同一串 `~/.ssh`，alice 敲出来是 `/home/alice/.ssh`，root 敲出来是 `/root/.ssh`，在你自己电脑上敲又是另一处。写法一样，指向不一样，这是它最容易骗人的地方。

`700` 和 `600` 是权限的数字写法。三个数字依次对应本人、同组用户、其他人，每一位由读（4）、写（2）、执行（1）相加得来。7 是读加写加执行，6 是读加写，0 是什么都没有。所以 `700` 表示只有本人能进这个目录，`600` 表示只有本人能读写这个文件。目录必须带那个 1，否则进不去；普通文件不需要执行位。完整的那张表在第十章 10.4。

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
```

这两条在**服务器**上敲。`id_ed25519` 是你的私钥，它只存在于**你自己的电脑**上，所以那条命令要在本机执行；如果你在服务器上敲，要么找不到文件，要么改到的是另一把无关的钥匙。

```bash
chmod 600 ~/.ssh/id_ed25519
```

为什么非要这样，这是因为 sshd 会检查权限。如果 `~/.ssh` 或 `authorized_keys` 的权限太宽，别的用户就能改里面的内容，往里面加一把自己的锁。那你的账户就不是你的了。sshd 发现这种情况，会直接拒绝用密钥登录，宁可让你进不来，也不让你在一个不安全的配置上进来。

服务器这侧由 sshd 检查；你自己的私钥那一侧由 `ssh` 客户端检查，权限太宽时它会提示 `UNPROTECTED PRIVATE KEY FILE` 并拒绝使用这把钥匙。两处检查的理由相同，都是怕别人能读、能改。

所以你看到 `Permission denied (publickey)` 的时候，先看权限，这一条能解决相当一部分问题。

```bash
ls -ld ~/.ssh
ls -l ~/.ssh/authorized_keys
```

正确的输出应该长这样。

```text
drwx------ 2 alice alice 4096 Nov  4 10:12 /home/alice/.ssh
-rw------- 1 alice alice  412 Nov  4 10:12 /home/alice/.ssh/authorized_keys
```

这两行开头的 `drwx------` 和 `-rw-------` 就是权限本身，只是换成了字母写法。第一个字符是类型。`d` 表示目录，`-` 表示普通文件。所以第一行是目录，第二行是文件。

后面九个字符分三组，每组三位，依次是本人、同组用户、其他人。有权限的位置写 `r`、`w`、`x`，没有就写 `-`。

| 看到的 | 拆开 | 对应 |
| --- | --- | --- |
| `drwx------` | 目录，本人 `rwx`，同组 `---`，其他人 `---` | 700 |
| `-rw-------` | 文件，本人 `rw-`，同组 `---`，其他人 `---` | 600 |

一行里剩下的部分是别的信息。`2` 和 `1` 是硬链接数，日常不用管。`alice alice` 是主人和所属的用户组。`4096` 和 `412` 是大小，单位字节。`Nov 4 10:12` 是最后修改时间。最后一段是完整路径。看权限的时候只盯前十个字符就够了。

## 9.6 云厂商给你的那个文件

买服务器的时候，很多平台会让你下载一个 `.pem` 或者 `.key` 文件。那个就是私钥，对应的是服务器上已经装好的公钥。

它只给你一次，页面关掉就再也下载不到了。丢了怎么办，去控制台重置，大部分平台支持重新绑定密钥对。

这个文件放哪很重要。放在项目目录里，然后顺手 `git add .`，就等于把钥匙上传到了 GitHub。这种事每年都在发生，扫描 GitHub 找私钥的机器人是二十四小时工作的。

## 9.7 建议关掉密码登录

密钥能用了之后，可以把密码登录关掉。在**服务器**上改 `/etc/ssh/sshd_config`，改完不要关掉当前这个已经登录的窗口——万一改错，新连接会被拒绝，只剩这个窗口能救你。

```text
PasswordAuthentication no
```

改完重启 sshd。但请一定在确认密钥能登录之后再改，并且保持当前这个窗口不要关，另开一个窗口测试。改错了至少还有一条活着的连接可以救你。

```bash
sudo systemctl restart ssh
```
