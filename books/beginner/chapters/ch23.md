# 安全和花钱的底线

> 这两件事的共同点是，出问题的时候都很突然。

## 23.1 十条规矩

**数据库和缓存不绑 `0.0.0.0`。** 第 3 章那个故事不是编的：扫描器二十四小时在工作，一个开放端口的 Redis 平均几小时内就会被找到，然后被写入公钥、装上挖矿程序。数据库、缓存、管理后台、Jupyter，这些东西的正确位置是 `127.0.0.1`，需要远程访问就走隧道或 VPN。

**密钥不进 git。** 第 14 章讲过，提交过一次就等于永久泄露，历史里删不干净。发现泄露的第一件事是去平台作废这把密钥，而不是先删文件——文件删了，密钥还在别人手里。

**不用 root 跑业务。** 建一个普通用户，systemd 里用 `User=` 指定。这样即使程序被攻破，攻击者拿到的也只是那个用户的权限，碰不到系统目录。

**关掉密码登录。** 密钥配好之后，把 `PasswordAuthentication` 改成 `no`。公网上的服务器每天被尝试几万次密码，关掉这一项能省掉大量噪音，也堵住了弱口令这条最常见的入口。

**能限定来源就限定。** 安全组的来源写自己的 IP 或公司出口 IP；管理后台加一层 Basic Auth；SSH 端口只对固定地址开放。这些限制平时感觉不到，出事时能挡住绝大部分自动扫描。

**大改动之前打快照。** 这是唯一能救回“我删错了”的东西。改 `sshd_config`、动防火墙、升级数据库之前，先打一个。云平台的快照按量收费，但比重新部署便宜得多。

**备份要异地。** 同一台机器上的备份，机器挂了就一起没了。至少放一份到对象存储或者另一台机器，而且要考虑“整个账号被误删”这种情况——备份所在的账号最好和主账号分开。

**最小权限。** 一个程序只需要读一个桶，就别给它整个账号的权限；一个脚本只需要重启一个服务，就别给它 `sudo ALL`。出事的时候，损失范围就是权限范围。

**看到 `777` 和 `curl | bash` 停一下。** 这两样在教程里很常见，在事故报告里也很常见。前者把文件对所有人开放，后者用一个陌生脚本以管理员身份执行，两者都没有回退余地。

**日志要留。** 出事之后最想知道的是“它是怎么进来的”。登录日志、应用日志、对象存储的访问日志，分属不同层，缺一层就会有一段空白。留多久取决于代价：便宜的存储留着，贵的滚动删除。

## 23.2 四个烧钱的坑

云服务的账单有一种特点：它不会某天突然翻十倍，而是在你忘记的某个地方慢慢涨，直到你点开账单。

**按量计费的机器忘了关。** GPU 机器一小时几十块，睡一觉就是几百，一周就是几千。用完当场销毁，不要只关机——关机后磁盘和公网 IP 通常还在计费。

**带宽和流量。** 按流量计费的机器，被人刷一次可能就是一晚上几百 G。在它前面加 CDN，或者设一个流量告警；如果是固定带宽，注意别把上行打满，否则同机其他服务会一起变慢。

**对象存储的请求费。** 存储本身很便宜，请求次数按万次计费。程序里一个小循环疯狂列目录、日志级别开成 debug 往对象存储写、前端每次刷新都去列一遍文件列表，账单都会很难看。更隐蔽的是跨地域流量和内网/公网域名的区别，第 16 章提过：同地域走内网域名不花钱，走公网域名按流量计费。

**快照和镜像堆积。** 每次打快照都占空间，自动快照策略如果没设保留数量，一年下来能存几十份。设置保留最近七份或者三十天，旧的自动删。

设一个账单告警，花五分钟，能救命。大部分云平台都有这个功能，阈值设成你月均消费的两倍；再加一个“预测超额”告警，效果更好。

## 23.3 备份的三二一

行业里有一句老话：三个副本，两种介质，一份异地。对个人项目可以简化成两条：至少两个地方，至少一个是自动的。

“两个地方”是为了防单点：本机一份、对象存储一份，硬盘坏了不至于全丢。“自动”是为了防自己：手动备份的问题是你会忘记，配一个定时任务，每天把数据库导出一份传到对象存储，比任何自觉都可靠。

还有一个常被忽略的点：**备份要能恢复才算备份**。每隔一段时间真的去恢复一次，你会发现不少备份其实是坏的——导出中途失败、权限不对、少了一个关键文件。没试过恢复的备份，只是一份心理安慰。

## 23.4 一个判断标准

遇到“要不要开这个端口”“要不要给这个权限”“要不要关这个检查”的时候，用一个问题来判断：最坏的情况发生时，我能承受吗。

数据库被拖走，能承受吗；服务器被拿去挖矿、账单来了，能承受吗；代码泄露、客户数据外流，能承受吗。承受不了的事，就不要为了省五分钟去冒险。

反过来，能承受的事就别过度设计。给个人博客配一套双因素加硬件密钥加堡垒机，是另一种浪费——时间、精力、还有你自己三个月后维护它的耐心。安全和成本都不是配置问题，是习惯问题：想清楚边界，然后让它变成默认动作，而不是每次临时判断。

> **这一章记住一句**
>
> 安全和成本都不是配置问题，是习惯问题。
