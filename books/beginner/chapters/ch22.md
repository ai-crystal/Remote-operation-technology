# 报错翻译器

> 报错不是判决书，是路标。

这一章是一张表，不用背。遇到的时候过来查，或者直接搜关键词。

## 22.1 连接类

| 原文 | 人话 | 第一步查什么 |
| --- | --- | --- |
| `Connection refused` | 找到了机器，但那个端口没人接 | 程序起了吗，端口号对吗 |
| `Connection timed out` | 包根本没到，或者被中途丢了 | 安全组、防火墙、IP 对不对 |
| `No route to host` | 路上没有能到达它的路径 | 网段、路由、VPN 是否生效 |
| `Network is unreachable` | 本机压根没有能出去的路 | 网卡、默认网关、VPN |
| `Connection reset by peer` | 对面把连接掐了 | 对端日志，是不是超时或限流 |
| `Broken pipe` | 你在往一根已经断了的管子里写 | 长连接保活，`ServerAliveInterval` |
| `Address already in use` | 这个端口已经有人占了 | `ss -lntp \| grep 端口` |
| `Cannot assign requested address` | 要绑的 IP 不属于这台机器 | `ip addr` 看有没有这个地址 |
| `Name or service not known` | 这个名字解析不出地址 | DNS、拼写、hosts |
| `Could not resolve hostname` | 同上，SSH 版本的说法 | 同上 |

## 22.2 SSH 与权限

| 原文 | 人话 | 第一步查什么 |
| --- | --- | --- |
| `Permission denied (publickey)` | 你的钥匙没对上服务器上的锁 | 公钥贴了吗，权限 600/700，用户名对吗 |
| `Permission denied (password)` | 密码错，或者密码登录被关了 | 密码，`PasswordAuthentication` |
| `Host key verification failed` | 这台机器的指纹和我记的不一样 | 是不是重装了，`ssh-keygen -R` |
| `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED` | 同上，更严重的警告版 | 先确认，别急着删记录 |
| `Too many authentication failures` | 试了太多把钥匙，被拒了 | `IdentitiesOnly yes`，指定 `-i` |
| `Load key: invalid format` | 私钥文件坏了或者不是私钥 | 是不是把 `.pub` 当私钥用了 |
| `UNPROTECTED PRIVATE KEY FILE` | 私钥权限太宽 | `chmod 600 私钥` |
| `sudo: command not found` | 这个用户没有 sudo 权限 | `sudoers`，或者用 root |
| `-bash: xxx: command not found` | 这个命令没装，或者不在 PATH 里 | `which`，装它，或者用绝对路径 |
| `Read-only file system` | 磁盘挂载成只读了，通常是出错保护 | `df -h`，`dmesg`，可能是磁盘满 |

## 22.3 HTTP 与部署

| 原文 | 人话 | 第一步查什么 |
| --- | --- | --- |
| `502 Bad Gateway` | 前台连不上后端 | 后端端口、进程状态 |
| `504 Gateway Timeout` | 后端接了但太久没回 | 应用日志，卡在哪个调用 |
| `413 Request Entity Too Large` | 上传的东西超过限制 | `client_max_body_size` |
| `404 Not Found` | 这个路径没东西 | 路由、路径前缀、反代规则 |
| `403 Forbidden` | 有东西但不给你 | 鉴权、文件权限、WAF |
| `500 Internal Server Error` | 程序自己崩了 | 应用日志里的堆栈 |
| `CORS policy` 相关 | 浏览器不允许跨域请求 | 后端加 `Access-Control-Allow-Origin` |
| `ERR_CONNECTION_REFUSED` | 浏览器版 Connection refused | 同第一张表 |
| `SSL_ERROR_RX_RECORD_TOO_LONG` | 用 https 访问了 http 端口 | 换协议，或换端口 |
| `nginx: [emerg] bind() to 0.0.0.0:80 failed` | 80 被别的程序占了 | `ss -lntp \| grep :80` |
| `Job for xxx.service failed` | 服务起不来 | `journalctl -u xxx -n 50` |
| `status=203/EXEC` | 启动命令的路径不对或者没有执行权限 | `ExecStart` 写绝对路径 |

## 22.4 存储与数据库

| 原文 | 人话 | 第一步查什么 |
| --- | --- | --- |
| `SignatureDoesNotMatch` | 签名算出来不一样 | 密钥、地域、路径编码 |
| `RequestTimeTooSkewed` | 你的时间和服务器差太多 | `date -u`，同步时间 |
| `AccessDenied` | 身份对，权限不够 | 策略里有没有这个操作 |
| `NoSuchBucket` | 桶名不对，或者地域不对 | 桶名、地域、endpoint |
| `NoSuchKey` | 对象不存在 | key 拼写，前缀 |
| `Access denied for user` | 数据库用户名密码错，或者来源 IP 没授权 | 账号、密码、`host` 字段 |
| `Too many connections` | 数据库连接数满了 | 连接池没关，慢查询堆积 |
| `Disk full` / `No space left on device` | 磁盘满了 | `df -h`，日志文件 |

## 22.5 一条使用建议

把报错的第一行原样复制去搜，不要只搜“打不开”“连接失败”这种词。

英文报错是精确的，它指向一个具体的层。中文描述是模糊的，它只描述你的感受。前者能搜到答案，后者只能搜到同样困惑的人。

如果搜索引擎给的结果太多，加上你的系统名和软件名。`502 nginx ubuntu` 比 `502 怎么解决` 有用得多。
