# 403 的一百种死法

> 403 不是“你没权限”这么简单，它是“服务器算出来的结果和你给的对不上”。

## 17.1 本地好好的，服务器上 403

代码在本地跑得好好的，能上传能下载。部署到服务器上，每一个请求都返回 403。

你把密钥复制了三遍，确认没有多余的空格。你把权限策略翻了一遍，是全权限。你开始怀疑是云厂商的问题。

这类问题在对象存储上极其常见，因为它的鉴权机制比普通的用户名密码复杂一层。

## 17.2 三个码不要混

**401** 是“你没告诉我你是谁”。没登录，或者令牌过期了。

**403** 是“我知道你是谁，但你不能做这件事”。身份是对的，权限不够。

**404** 是“这里没有这个东西”。

对象存储有时候会用 403 代替 404，故意不告诉你某个文件到底存不存在，防止别人拿它探测。所以看到 403 不要立刻断定是权限问题。

## 17.3 签名是怎么算的

对象存储不用密码，用签名。过程大概是这样的。

你的程序把这次请求的几个要素凑在一起，请求方法、路径、时间、host、内容的哈希，再加上你的密钥，算一个哈希值。这个值附在请求头上，或者拼在 URL 里。

服务器收到之后，用同样的方法再算一遍。两边一样就放行。

关键在于“同样的方法”。任何一个输入不同，算出来的值就完全不同。所以下面这些东西只要有一项不对，就会失败。

| 出错的地方 | 表现 | 怎么查 |
| --- | --- | --- |
| 密钥写错或有多余空格 | `SignatureDoesNotMatch` | 打印长度，看首尾是否有空白 |
| 本机时间不准 | `RequestTimeTooSkewed` | `date -u` 看时间，差超过十五分钟就不行 |
| 地域或 endpoint 写错 | 连接失败或签名不符 | 核对桶在哪个地域 |
| key 里有中文或空格 | 签名不符或 404 | 确认编码方式一致 |
| 请求头被中间层改过 | 签名不符 | 看 nginx 是否改写了头 |
| 权限策略没给这个操作 | `AccessDenied` | 看策略里有没有 `s3:GetObject` |
| 桶名写错 | `NoSuchBucket`，有时是 403 | 复制粘贴核对 |
| 用了临时凭证但没带 token | `AccessDenied` 或签名错 | 三个值要一起用 |

## 17.4 那个关于时间的故事

某一类 403 特别有意思，只在服务器上出现，本地永远复现不了。

原因是服务器的系统时间和真实时间差了十几分钟。签名里带时间戳，服务器算出来的和别人算出来的差了太多，被拒绝。

为什么服务器时间会不准。虚拟机暂停、长时间高负载、时钟同步服务没开，都会导致漂移。云厂商一般会自动同步，但有些精简镜像把这个服务关掉了。

下面两条在服务器上敲。`date -u` 看 UTC 时间，和你本地的时间对一下，差几分钟以上就算异常。

```bash
date -u
sudo systemctl restart systemd-timesyncd
```

这一条能解决相当一部分“莫名其妙的 403”，尤其是那种重启之后就好了、过几天又出现的。

## 17.5 排查顺序

不要一上来就改权限策略，那是最后一步。

**第一步，用最小可复现的例子。** 官方 SDK 的示例代码，只改密钥、桶名、地域，跑一次。能通说明你的代码有问题，不能通说明环境或者凭证有问题。这一步把范围砍掉一半。

**第二步，看具体的错误码。** 403 只是一个类别，真正的信息在响应体里，里面有 `Code` 字段。把那个字段拿去搜，比搜 403 有用一百倍。

**第三步，对时间。** 一条命令的事，先排除掉。

**第四步，对地域和 endpoint。** 桶在广州，你连的是上海，签名对不上。这是跨地域复制代码时最常见的错。

**第五步，才去看权限策略。** 策略里要分清“桶级操作”和“对象级操作”，列目录和读文件是两种权限。

## 17.6 一个习惯

遇到 403 的时候，先把响应体完整打印出来。

```python
try:
    client.get_object(...)
except Exception as e:
    print(e)
    print(getattr(e, "response", None))
```

大部分 SDK 的异常对象里带着服务端返回的原始内容，里面有错误码、请求 ID、甚至一句人话解释。请求 ID 还能拿去问厂商的技术支持。

很多人只看到“403 Forbidden”就开始猜，其实答案就在下面几行里，只是被异常处理吞掉了。

> **这一章记住一句**
>
> 403 先看错误码，再看时间，最后才看权限。

第四篇结束。文件有了地方放，服务能对外的部分也齐了。第五篇讲一个反向的问题，如果那台机器根本没有公网地址，你怎么进去。
