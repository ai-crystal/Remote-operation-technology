# 云上的仓库

> 对象存储是仓库，不是硬盘。取货要凭单。

## 16.1 桶是什么

AI 说，把图片上传到 COS，代码里出现了 `bucket`、`key`、`endpoint` 这些词。你大概能猜出是云存储，但不知道它们各自指什么。

对象存储的结构只有两层。

最上面是桶，英文 bucket。一个桶是一个大容器，你所有的东西都装在里面。桶的名字在整个云平台的所有用户之间是唯一的，所有人共用一个命名空间，不能重名。
所以你会看到有人在桶名后面加一串数字，比如 `myapp-1250000000`，这不是装饰，是因为 `myapp` 已经被别人用了，所以你需要换个名字，或者加点后缀让名字跟已有的区分开。

下面一层是对象，object。一个对象就是一份数据加上一些说明，有内容，有大小，有类型，有名字。

对象的名字叫 key。它是一段字符串，比如 `images/2026/11/cat.jpg`。中间那些斜杠看起来像目录，其实不是。对象存储里没有目录这个概念，斜杠只是名字里的一个普通字符。

这就是它和硬盘最大的区别。你不能对它 `cd`，不能对它 `ls` 一个不存在的目录，也不会因为建了目录而占用空间。所谓“列出某个文件夹”，实际动作是按前缀查询，把所有以 `images/2026/11/` 开头的 key 列出来。

这个区别在写代码时会露出来。有的 SDK 提供 `list_objects(prefix=...)`，没有 `list_dir`。理解了这一点，你就不会去找“怎么创建目录”这种不存在的操作。

## 16.2 一个对象的地址

```text
https://myapp-1250000000.cos.ap-guangzhou.myqcloud.com/images/2026/11/cat.jpg
```

拆开看。`myapp-1250000000` 是桶名，`cos.ap-guangzhou` 是地域和产品，`myqcloud.com` 是厂商域名，后面那一串是 key。

AWS 的写法略有不同，桶名放在域名最前面，`https://myapp.s3.us-east-1.amazonaws.com/...`。原理一样。

有一点要注意，桶是有地域的。北京的桶和广州的桶是两个不同的地方，接口地址不同，跨地域访问会慢，也可能会额外收费。如果你在代码里写死了地域，换一个桶就得改配置。

## 16.3 三种让人看到东西的办法

默认情况下，桶是私有的，谁也访问不了。让别人看到有几种办法。

**公开读。** 把整个桶或者某个前缀设成公开，任何人都能用 URL 直接访问。适合网站的静态资源，图片、样式、脚本。缺点是任何人都能下载，也容易被别人盗链，用你的流量。

**签名 URL。** 生成一个带签名的临时链接，有效期可以是几分钟也可以是几小时，过期就失效。适合给用户下载私有文件，比如付费课的视频、报表。

**带身份的请求。** 你的服务器拿着密钥，通过 SDK 直接调接口。适合后端之间的操作，比如上传用户上传的附件。

第一种最省事但最危险，第二种最常用，第三种是内部操作。选错会出问题，要么数据裸奔，要么用户点开链接看到 403。

## 16.4 存储级别和生命周期

对象存储按量收费，存着就收钱。但不同“冷热”的数据价格差很多。

热数据随时要读，价格最高。冷数据很少读，存起来便宜，但取出来要等，还要付取回费用。还有归档级别，更便宜，取回要几小时。

这些级别可以靠规则自动切换。比如设一条规则，超过三十天的日志自动转成低频，超过一年的自动删掉。这件事叫生命周期管理，配一次就不用管了。

不配的后果是账单慢慢涨。你有几百 G 的旧日志一直躺在最贵的那一档里，每个月都在为它付钱。

## 16.5 什么时候用它，什么时候不用

**适合。** 用户上传的图片、视频、附件。网站静态资源。备份和归档。数据集的存放和分享。需要多个服务器共享访问的文件。

**不适合。** 数据库文件。频繁随机读写的小文件。需要文件锁的场景。需要挂载成一个目录直接操作的场景。

第二条特别值得说。对象存储的每次请求都有延迟，通常是几十毫秒。你在服务器上读写本地文件是微秒级的。如果你的程序每分钟要读几千次小文件，用对象存储会慢到不能用，而且请求次数也要钱。

第三条也常见。有些老程序假设自己在一个普通文件系统上，会做 `open`、`seek`、`flock` 这些操作，对象存储不支持，或者支持得很别扭。这种程序需要先改造，或者用云厂商提供的文件存储，那是另一个产品。
