# 云上的仓库

> 对象存储是仓库，不是硬盘。取货要凭单。

## 16.1 桶是什么

AI 帮你写上传图片的代码，里面出现了 `bucket`、`key`、`endpoint` 这些词。你大概知道这是云存储，但不知道它们各自指什么，改错一个就报错。对象存储的结构只有两层：上面是桶，下面装对象。

**桶**（bucket）是一个大容器，你所有的东西都装在里面。桶名在整个云平台的所有用户之间是唯一的——所有人共用一个命名空间，不能重名。所以你会看到桶名后面挂着一串数字，比如 `myapp-1250000000`，那不是装饰：`myapp` 早被别人占了，这串数字是你的账号 ID（腾讯云叫 APPID），加上它才保证全球唯一。

桶名有格式限制：通常三到六十三个字符，只能用小写字母、数字和连字符，不能以连字符开头或结尾，也不能用大写的驼峰。这些规则各家略有差异，但方向一致——它最终要拼进域名，所以必须符合域名的规矩。

**对象**（object）是桶里的一份数据，由四部分组成：名字（key）、内容（数据本身）、元数据（大小、类型、自定义的键值对）、以及访问控制信息。你上传一张图，看到的只是“一个文件”，实际上这些信息都存在。

## 16.2 key 不是目录

对象的名字叫 key，是一段字符串，比如 `images/2026/11/cat.jpg`。中间那些斜杠看起来像目录，其实不是。对象存储里没有目录这个概念，斜杠只是名字里的一个普通字符，和字母 `i`、`m` 没有区别。

这就是它和硬盘最大的区别。你不能对它 `cd`，不能 `ls` 一个不存在的目录，也不会因为“建了目录”而占用空间——因为根本没有目录可建。所谓“列出某个文件夹”，实际动作是按前缀查询：把所有以 `images/2026/11/` 开头的 key 列出来。

这个区别在写代码时会直接露出来。SDK 里通常只有 `list_objects(prefix="images/2026/11/")`，没有 `list_dir`。理解了这一点，你就不会去找“怎么创建目录”这种不存在的操作，也不会奇怪为什么“删目录”要一个一个删。

迁移数据时还会遇到另一面：从本地文件系统往对象存储搬，目录结构会自动变成 key 里的斜杠，不用手动建目录；反过来从对象存储搬到本地，要看工具怎么解释这些斜杠——有的会建目录，有的会把整个 key 当成一个文件名。

## 16.3 一个对象的地址

```text
https://myapp-1250000000.cos.ap-guangzhou.myqcloud.com/images/2026/11/cat.jpg
```

拆开看：`myapp-1250000000` 是桶名，`cos` 是产品，`ap-guangzhou` 是地域，`myqcloud.com` 是厂商域名，最后那一串是 key。AWS 的写法略有不同，桶名直接放在域名最前面（`https://myapp.s3.us-east-1.amazonaws.com/...`），原理一样。有两个细节容易踩。

一是**桶有地域**。北京的桶和广州的桶是两个不同的地方，接口地址不同，跨地域访问会慢，也可能额外收费。代码里写死了地域，换一个桶就得改配置；把地域写进配置文件而不是硬编码在代码里，能省掉很多麻烦。

二是**同一个桶通常有两个域名**：公网域名和内网域名。服务器和桶在同一个地域时，走内网域名不花流量费、速度也快；走公网域名则按出网流量计费。这个差别在账单上非常明显，尤其是每天传几百 G 的场景。

## 16.4 三种让人看到东西的办法

默认情况下桶是私有的，谁也访问不了。让别人看到有几种办法，各有各的代价。

**公开读**：把整个桶或者某个前缀设成公开，任何人都能用 URL 直接访问。适合网站的静态资源——图片、样式、脚本。缺点是任何人都能下载，也容易被别人盗链，用你的流量。控制手段是防盗链（检查请求头里的 `Referer`）和 CDN 的鉴权。

**签名 URL**：生成一个带签名的临时链接，有效期可以是几分钟也可以是几小时，过期就失效。适合给用户下载私有文件，比如付费课程的视频、导出的报表。它的好处是不用把密钥给对方，坏处是链接一旦泄露，在有效期内谁都能用。

**带身份的请求**：你的服务器拿着密钥，通过 SDK 直接调接口。适合后端之间的操作，比如接收用户上传的附件、定时备份。密钥只存在服务器上，不经过浏览器。

第一种最省事但最危险，第二种最常用，第三种是内部操作。选错会出问题：要么数据裸奔，要么用户点开链接看到 403。

还有一件和浏览器相关的事：如果网页用 JavaScript 直接上传到对象存储（而不是经过你的服务器），就要**在云控制台的桶设置里**配置 **CORS**，明确允许哪个域名、哪些方法、哪些请求头。不配的话，浏览器会在预检请求那一步就拦下来，控制台里报的是跨域错误，而不是 403，很容易查错方向。

## 16.5 存储级别和生命周期

对象存储按量收费，存着就收钱。但不同“冷热”的数据价格差很多，于是有了存储级别。

- **标准**：随时要读，延迟最低，价格最高。
- **低频**：一个月读几次，存储便宜一些，但每次读取有额外的取回费用。
- **归档**：一年读一两次，存储很便宜，取回要等几分钟到几小时。
- **深度归档**：几乎不读，只做合规留存，取回可能要几小时甚至更久。

这些级别可以靠规则自动切换。比如设一条规则：超过三十天的日志自动转低频，超过一年自动转归档，超过三年自动删除。这件事叫生命周期管理，**在云控制台的桶设置里**配，配一次就不用管了——它不是让你在服务器上写一个定时脚本去删文件。

不配的后果是账单慢慢涨：几百 G 的旧日志一直躺在最贵的那一档里，每个月都在为它付钱。更隐蔽的是取回费用——把归档数据当成热数据频繁读，存储费省下来的钱会从取回费里加倍还回去。

## 16.6 什么时候用它，什么时候不用

**适合**：用户上传的图片、视频、附件；网站静态资源；备份和归档；数据集的分发；需要多台服务器共享访问的文件。

**不适合**：数据库文件；频繁随机读写的小文件；需要文件锁的场景；需要挂载成目录直接操作的场景。

第二条值得展开。对象存储的每次请求都有网络延迟，通常几十毫秒，而本地读写是微秒级。如果你的程序每分钟要读几千次小文件，用对象存储会慢到不能用，而且请求次数本身也要钱——一次 GET 几分钱听起来不多，一天几百万次就是另一回事了。

第三条也常见。有些老程序假设自己在一个普通文件系统上，会做 `open`、`seek`、`flock` 这类操作，对象存储不支持，或者支持得很别扭。这种程序需要先改造，或者改用云厂商的“文件存储”（NAS），那是另一个产品，按容量收费，能挂载成目录，但性能和扩展性都比对象存储差。
