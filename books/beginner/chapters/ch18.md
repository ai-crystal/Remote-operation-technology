# 挖一条地道

> 隧道不是穿墙，是把管子插在已经开着的门里。

## 18.1 一台看不见的机器

公司的测试环境里有一台机器，地址是 `10.0.0.9`，上面跑了一个管理后台，只能在公司内网打开。你回到家，突然需要上去看一眼某个配置。

直接 `ping 10.0.0.9` 是不通的。这个地址只在公司内网有意义，就像邻居家的门牌号，出了这个小区没人认。你手里唯一能连的，是公司的跳板机 `jump.example.com`，它有公网地址，你能 SSH 上去，而它同时连着内网，两个世界都够得着。

问题出在下一步：你登录跳板机之后，只能在它的命令行里敲命令，而管理后台是一个网页。浏览器在你自己的电脑上，它够不着 `10.0.0.9`。你不能把浏览器搬到跳板机上去，也不想为了看一眼配置就在服务器上装一个图形界面。

需要的是这样一条路：让浏览器以为自己连的是本机的一个端口，实际的数据却穿过跳板机，落到那台看不见的机器上。

## 18.2 SSH 隧道这个想法

SSH 的连接本身就是一条加密通道，从你的电脑通到跳板机。既然这条管道已经通了，能不能顺手在里面运点别的东西？能，这就是端口转发，也叫 SSH 隧道。下面这条命令在**你自己的电脑**上敲，不要在跳板机上敲：

```bash
ssh -L 8080:10.0.0.9:80 alice@jump.example.com
```

`-L` 是本地转发，后面跟三段，用冒号隔开：**你电脑上的**端口 `8080`、目标地址 `10.0.0.9`、目标端口 `80`。

整句话的意思是：ssh 客户端会在**你的电脑上开一个 8080 端口，坐在那里等本机上的程序来连**。你的浏览器（或者数据库客户端）连这个端口，连进来的流量就会被它接住，塞进 SSH 通道送到跳板机，再由跳板机去连 `10.0.0.9` 的 80 端口。

这里容易读反，值得停一下。8080 这个端口在你这一端是**监听**的一方，不是发起的一方：不是“你从 8080 连出去”，而是“你的浏览器连到 127.0.0.1:8080，ssh 客户端在那一头接着”。所以一句话里有两个独立的连接：浏览器 → 本机 8080（一段普通的本地 TCP），ssh 客户端 → 跳板机（一段加密的长连接）；再加上跳板机 → 目标机，一共三段。第 3 章讲过“监听和连接是两件事”，这里正好是它的实际用法——同一个端口号，在转发的这一端是“听”，在浏览器那一端是“连”。

登录之后不会出现命令提示符，这条命令就停在那里，像一个守门人。这时打开浏览器访问 `http://127.0.0.1:8080`，看到的就是那台内网机器的管理后台。

数据的实际路径是这样的：浏览器把请求发给你电脑上的 8080，ssh 客户端接住，塞进加密通道送到跳板机；跳板机拆开，替你去连 `10.0.0.9:80`，拿到回应再塞回通道传给你。对你来说，那个内网服务就好像长在自己电脑上。

这里有两个容易搞错的点。第一，`10.0.0.9` 是**跳板机**去连的，不是你的电脑去连的，所以你的电脑根本不需要认识这个地址，也不用改 hosts。第二，本地端口可以随便换，8080 被占了就换 18080，只要浏览器跟着改。

还有一个细节要交代：上面那个网址里的 `127.0.0.1` 是从哪来的？它是**你自己电脑上的回环地址**，不是 `10.0.0.9`，也不是跳板机的地址。第 3 章讲过，回环地址永远指向“这台机器自己”，数据不出网卡。`-L 8080:...` 不写绑定地址时，默认就绑在 `127.0.0.1` 上，也就是说只有本机能连这个 8080；正因如此，你访问的地址才写成 `http://127.0.0.1:8080`。写成 `localhost:8080` 是一样的，`localhost` 只是一个指向 `127.0.0.1` 的名字。你看到的管理后台内容来自 `10.0.0.9`，但入口是本地这个 8080——真正的内容是被“搬”过来的，地址并没有变。

实际使用时还有几个参数值得知道。加 `-N` 表示“只做转发，不给我 shell”，省掉一个没用的终端；加 `-f` 让它转到后台运行；加 `-o ExitOnForwardFailure=yes` 让转发失败时直接退出，而不是假装连上了却什么都没通。要同时开好几个服务，就写多个 `-L`：

```bash
ssh -N -f -L 8080:10.0.0.9:80 -L 3306:10.0.0.8:3306 alice@jump.example.com
```

这一条同时把网页和数据库搬了过来：本机连 `127.0.0.1:3306`，连到的就是内网那台 `10.0.0.8` 上的数据库——同样是本机的回环地址，内容来自远端。

## 18.3 一个默认值和它的风险

`-L 8080:...` 默认只绑 `127.0.0.1`，也就是只有你这台电脑能用。这通常是你要的，但也有人为了“让同事也能用”，改成 `-L 0.0.0.0:8080:...`。

这一改，同一个办公室的人就能**通过你的电脑**访问那个内网服务了。这句话需要展开，否则很容易想歪。

所谓“通过你的电脑”，不是让同事登录到你的电脑上操作，而是**把你的电脑当成一座桥**。你的笔记本在办公室的局域网里有一个地址，比如 `192.168.1.23`；绑定 `0.0.0.0` 之后，ssh 客户端不只在 `127.0.0.1` 上听，也在 `192.168.1.23` 上听。于是同事在他的浏览器里输入 `http://192.168.1.23:8080`，请求就落到你的电脑上；你的 ssh 客户端接住，顺着那条隧道送到跳板机，再由跳板机去连 `10.0.0.9`。同事从头到尾没有登录你的电脑，他只是在访问你电脑上的一个端口，你的电脑替他把请求转了出去。

完整的路径变成这样：

```text
同事的浏览器 → 192.168.1.23:8080（你的电脑）
             → ssh 客户端 → 跳板机 → 10.0.0.9:80
```

这也是为什么风险不小。同事用的是**你的账号、你的隧道、你的权限**，目标机那边看到的访问全部记在你头上；你并不知道他看了什么、改了什么。你等于替整个办公室开了一扇门，而钥匙孔上写的是你的名字。

那 `0.0.0.0` 是不是意味着公司外面的人也能用？不一定，取决于你的机器在网络里的位置。`0.0.0.0` 只表示“本机所有网卡都听”，能不能被外面找到是另一回事：如果这台笔记本在办公室或家里的局域网里，它只有一个 `192.168.x.x` 的内网地址，外面的人根本路由不过来，只有同一局域网的人能连；如果这台机器本身有公网 IP，云主机的安全组又放行了这个端口，那才是真的对全网开放，谁扫到谁就能用。第 3 章讲 NAT 时说过这件事——地址转换让外面连不进来，这是唯一的保护。所以“绑 `0.0.0.0` 危不危险”，要看它绑在哪台机器上：家里的笔记本是“对邻居开放”，云服务器是“对全世界开放”。

第 3 章讲 `0.0.0.0` 时说的就是这个风险，在隧道上同样成立。需要别人临时用一下，再开；用完就关。长期需求应该走公司的正规通道，而不是某个人的笔记本。

## 18.4 反过来：把家里的东西给外面看

还有一种需求方向完全相反：你在自己电脑上跑了一个服务，想让公网上的某台服务器访问它。比如本地调试微信回调，微信的服务器要能访问到你的接口；或者给客户演示一个还没上线的页面。`-R` 就是干这个的，叫远程转发：

```bash
ssh -R 9000:127.0.0.1:3000 alice@203.0.113.24
```

注意这条命令**仍然在你自己的电脑上敲**，`203.0.113.24` 只是对端，不要先 `ssh` 上去再执行。

意思是：让那台服务器的 9000 端口指向你本机——所有连到它的请求，通过这条 SSH 通道转回你本地的 3000。配置允许的话，任何人访问 `203.0.113.24:9000`，实际连的是你家那台电脑。

这就是内网穿透的基本原理。市面上那些工具——frp、ngrok、cloudflared、Tailscale——做的事情本质相同，只是把这条通道做得更稳、更好配，还顺带解决了域名、证书和断线重连。它们面对的是第 1 章那个老问题：家里的电脑没有公网地址，外面的人找不到它。`-R` 是临时办法，专用工具是长期办法。

有一个限制必须知道：服务器上的 sshd 默认只允许把这种转发端口绑在 `127.0.0.1`，外面访问不到。要用得让管理员把 `GatewayPorts` 改成 `yes` 或 `clientspecified`，然后重启 sshd。这件事你自己改不了，也不该偷偷改。

## 18.5 还有两种

`-D` 把 SSH 当成一个 SOCKS 代理，命令同样在你自己的电脑上敲：

```bash
ssh -D 127.0.0.1:1080 alice@jump.example.com
```

它会在**你的电脑**上开一个 1080 端口的代理，浏览器把代理地址填成 `127.0.0.1:1080`（这里的 `127.0.0.1` 是你的电脑，不是跳板机），之后所有请求都通过这条通道，由跳板机替你去连。它和 `-L` 的区别是目标不固定：`-L` 一次指定一个目标，`-D` 是运行时才决定连哪里，适合“临时从另一个地方上网”的场景。`-J` 是跳板机连跳板机：

```bash
ssh -J alice@jump1,alice@jump2 alice@10.0.0.9
```

这条也是在你自己的电脑上敲。不用先登录第一台、再从它登录第二台，一条命令直达。它的好处是本地不需要为中间那两台配置密钥，认证在链条上逐段完成；中间机器只转发字节流，看不到最终目标机的凭据。这比“先 ssh 到跳板机，再手动 ssh”更安全，因为后者会把你的私钥暴露在跳板机上。配置文件里对应的是 `ProxyJump`，写法更清爽，第 19 章讲堡垒机时会再看到它。

## 18.6 别忘了它是什么

隧道很有用，但它做的事实上是绕过网络边界。公司把数据库放在内网，就是为了不让外面直接连。你挖一条隧道连上去，从技术上讲没有破坏任何东西，从管理上讲是绕过了人家的安全设计。很多公司的安全策略明确禁止这种行为，而且流量审计能看得出来——一条长时间保持的 SSH 连接，带着持续的双向流量，特征很明显。自己家的实验环境随便玩。公司的环境，先问一句能不能。

> **这一章记住一句**
>
> `-L` 把远方搬到本地，`-R` 把本地送到远方。

下一章讲正规军怎么做这件事。公司不会给你开一条隧道，它们有班车和前台。
