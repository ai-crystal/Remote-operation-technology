# 屋里的规矩

> Linux 里没有“我的文档”，只有路径。

## 10.1 一条看不懂的命令

这一章的命令都在服务器上敲。你 ssh 登录之后那个窗口，提示符通常长成 `root@xxx:~#` 或者 `alice@xxx:~$`，看到它就说明你在服务器里。AI 给你一行。

```bash
sudo nano /etc/nginx/nginx.conf
```

这里面的每个部分你都不确定。`sudo` 是什么，`/etc` 是什么，为什么前面要加个斜杠，`nano` 又是什么。这一章把这几个问号都解决掉。不追求系统，只求看懂 AI 给的命令。

## 10.2 树状的房子

Linux 的文件系统是一棵树，从 `/` 开始，这个符号叫根。所有的东西都挂在它下面，没有 C 盘 D 盘的概念。

| 路径 | 放什么 | 你会不会去 |
| --- | --- | --- |
| `/etc` | 各种配置 | 会，改 nginx、ssh 都在这 |
| `/home/用户名` | 你的个人目录 | 会，写代码、放数据 |
| `/root` | 管理员的家 | 偶尔 |
| `/var/log` | 日志 | 会，排错必看 |
| `/opt` | 额外装的软件 | 偶尔 |
| `/tmp` | 临时文件，重启可能清空 | 会，但别放重要的东西 |
| `/usr/bin` | 系统命令 | 一般不用管 |

`~` 这个符号代表当前用户的家目录。你是 alice，`~` 就是 `/home/alice`。你是 root，`~` 就是 `/root`。想知道当前用户的家目录到底是哪个，敲一句 `echo $HOME`。

`.` 是当前目录，`..` 是上一级。`cd ..` 往上走一层，`cd ~` 回家。这三个符号你会在所有教程里看到。

## 10.3 sudo 是借权限

Linux 里每个文件都有主人。系统的配置文件主人是 root，普通用户改不了。`sudo` 的意思是，以管理员身份执行这一条命令。它借给你权限，执行完就还回去，你还是你自己。

这就是为什么 AI 给的命令里 `sudo` 时有时无。改系统配置要，改你自己家目录里的文件不要，装软件要，跑你自己的脚本不要。看到 `sudo` 就知道这条命令在动系统层面的东西，值得多看一眼。

有一件事值得警惕。AI 有时候会给你 `sudo` 加上一串很长的命令，或者 `curl 某个地址 | sudo bash`。后者的意思是下载一个脚本然后直接用管理员权限执行。这种命令等于把家门钥匙交给一个陌生网站，除非你完全信任来源，否则不要执行。

## 10.4 权限那三个字母

```bash
ls -l
```

输出里每一行前面有一段东西，像 `-rw-r--r--`。这是权限。拆开看，第一位是类型，`-` 是文件，`d` 是目录。后面每三位一组，分别对应主人、同组用户、其他人。每组里的 `rwx` 是读、写、执行。用数字表示更方便。r 是 4，w 是 2，x 是 1，加起来。

| 数字 | 含义 | 常见用途 |
| --- | --- | --- |
| 644 | 主人能读写，别人只能读 | 普通文件、公钥 |
| 600 | 只有主人能读写 | 私钥、配置文件里的密码 |
| 755 | 主人能读写执行，别人能读和执行 | 目录、可执行程序 |
| 777 | 所有人都能读写执行 | 几乎永远不该出现 |

`chmod 600 文件名` 就是把权限设成 600。第九章提到的私钥必须 600，就是这个东西。

`chmod 777` 在教程里出现得非常多，因为它是“让权限问题消失”的最快办法。代价是任何能登录这台机器的人都能改这个文件，包括那些通过别的漏洞进来的攻击者。你为了解决一个访问问题，把一堵墙拆了。

遇到 AI 让你 `chmod 777`，可以问它一句，能不能只给需要的那一组用户。大部分时候答案是能。

## 10.5 进程和它的号

程序跑起来，就成了一个进程。每个进程有一个编号，叫 PID。

```bash
ps -ef | grep python
top
```

`ps` 是拍一张快照，`top` 是实时看着。看到某个进程占满 CPU，记下它的 PID，然后。

```bash
kill 12345
```

多数程序收到这个信号会自己收拾东西退出。赖着不走的用 `kill -9`，但那是强杀，可能留下没写完的文件。

## 10.6 日志在哪

出问题的时候，日志比代码有用。系统服务的日志用 `journalctl`。

```bash
journalctl -u nginx -n 50
journalctl -u nginx -f
```

`-n 50` 是看最后五十行，`-f` 是实时跟着看，像 `tail -f`。很多程序自己写日志文件，在 `/var/log/` 下面，或者它的工作目录里。你的应用日志在哪，取决于你怎么启动它，这也是第十一章要解决的问题。

## 10.7 装软件

```bash
sudo apt update && sudo apt install nginx    # Ubuntu / Debian
sudo yum install nginx                        # CentOS / Rocky
```

`apt` 是包管理器，它从软件源下载、安装、处理依赖。Python 的 `pip`、Node 的 `npm`、Rust 的 `cargo` 是同一个思路，只是管的范围不一样。

一个新手常犯的错是用 `pip install` 装系统级的东西，装到一半报权限错误，然后加上 `sudo`，把包装进了系统 Python，后来和系统自带的版本打架。正确做法是在虚拟环境里装，AI 一般会帮你处理，看到 `venv` 或者 `conda` 就说明它在做这件事。

> **这一章记住一句**
>
> 系统的东西要 sudo，你自己的东西不要。看到 777 先停一下。

第二篇结束了。你现在能进到那台机器里，看懂大部分命令在干什么。第三篇开始解决一个更实际的问题，怎么让程序在你关掉窗口之后还活着。
