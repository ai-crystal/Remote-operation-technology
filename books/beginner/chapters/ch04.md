# 城市的黄页

> 域名只是地址簿里的一行字，它不保证那个地址上有人。

## 4.1 改完之后不生效

你买了个域名，在云厂商的控制台里把它指向服务器，然后打开浏览器。

看到的还是上一次那个页面，或者一个“无法访问”。

你又等了十分钟，还是这样。你开始怀疑自己是不是哪里填错了，于是把配置改了又改，越改越乱。第二天早上再看，好了。

这件事有两个可能的解释，一个是缓存，一个是备案。两个都值得知道，因为它们是两件完全不同的事，却长得一模一样。

## 4.2 名字是给人记的

机器只认数字。`203.0.113.24` 这样的地址，机器用起来很方便，人记不住。所以有了域名，`example.com` 这种。

域名和 IP 的关系，像黄页上的名字和电话。你查“老王修车”，翻到号码，拨过去。你不会记号码，你记名字。

把这个动作自动化，就是域名系统，简称 DNS。你在浏览器里输入 `example.com`，浏览器先去问一句，这个名字对应的地址是多少。拿到地址之后，才去连。

这个“问一句”的过程你感觉不到，通常在几十毫秒里完成。但它背后有几层人在接力。

## 4.3 谁在回答你

你的电脑先看自己记的小本子，本机缓存。没有的话去问运营商提供的 DNS 服务器，通常是你家路由器转发过去的。

运营商那台服务器也不知道答案，但它知道该问谁。它先去问根服务器，根服务器说 `.com` 归那边管。它再去问 `.com` 的服务器，那边说 `example.com` 的地址记录在某某服务器上。它最后去问那台，拿到 IP，回来告诉你，顺便自己记一份。

下一次别人再问同一个名字，它就不用跑这一圈了，直接给。这个“记一份”的行为叫缓存，缓存多久由一个叫 TTL 的数值决定，单位是秒，常见的是 600 或者 3600。

改了配置不生效，最可能就是旧答案还在某个缓存里没到期。你本地、路由器、运营商，三层都可能有。等 TTL 过去，自然就对了。着急的话可以换个网络试，手机热点经常能看到新结果，因为它走的是另一条线路。

## 4.4 这张表归谁管

上一节说到“去问一句”，但没说是谁在答。域名这套东西不是一家公司在管，从头到尾有四拨人。

| 角色 | 干什么 | 例子 |
| --- | --- | --- |
| 注册局 | 维护一个后缀的中央库 | `.com` 是 Verisign，`.cn` 是 CNNIC |
| 注册商 | 把名字卖给你，替你登记 | 阿里云、腾讯云、GoDaddy |
| 权威服务器 | 回答这个名字指向哪 | 注册商默认给的，或者你自己托管 |
| 递归解析器 | 替你去问，顺手缓存 | 运营商、`8.8.8.8`、`114.114.114.114` |

规则由 ICANN 定。它不直接卖域名，只负责决定谁可以管哪个后缀。

你实际打交道的只有注册商。你在它的页面上搜一个名字，它去注册局查这个名字还在不在，在就写进中央库，然后收你钱。

真正“翻译”的动作发生在递归解析器上。它替你去问，问到了缓存一份，下一次别人问同一个名字，它直接把缓存给出去。你改记录之后要等 TTL 过期才生效，等的是它手里那份旧答案。

### 4.4.1 重名算谁的

算先付钱那个。

同一个后缀下，一个名字只能登记一次。注册局那张中央库就是唯一索引，注册商提交的时候会被它挡住，所以不存在“两个人都注册了 example.com”这种事。

每个顶级域（如 .com, .cn）都有一个自己专属的“中央库”，由该域的注册局负责运营和维护。这些数据库分散在全球各地符合高安全标准的数据中心内，并通过技术协议协同工作，共同构成了我们感知到的、逻辑上唯一的域名系统。
ICANN（互联网名称与数字地址分配机构）则在这个体系中扮演着协调者和政策制定者的角色，负责授权和监督各个注册局的运行。

例如，.com / .net 的注册局长期由 Verisign 运营。不同后缀可以同名，但实际上，`example.com` 和 `example.net` 是两家人，各管各的，互不相干。

你也不“拥有”它，你是在租。按年付费，到期有几十天宽限期，再不续就进入赎回期，赎回要加钱，过了赎回期释放回公共池，任何人都能买走。所以严格说，域名是“我租的这一段”，不是你名下的资产。

子域名是另一回事。`blog.example.com` 不用注册。你手里有 `example.com`，下面怎么分是你自己的事，想叫 `blog` 就叫 `blog`，想叫 `a1` 就叫 `a1`。它在全世界唯一，靠的是主域名唯一，加上你自己起的这一段。

### 4.4.2 技术管不了的部分

DNS 只管“这个名字对应哪个地址”，它不管这个名字该不该归你。

同名不同后缀的两家公司，技术上完全正常。名字撞上别人的商标，走的是投诉和仲裁，不是改一条记录能解决的。

还有一件事容易误会。唯一性靠的是注册局那张表，不是查询时的校验。你完全可以在自己电脑的 hosts 文件里写一行 `203.0.113.24 example.com`，从此这台机器访问 `example.com` 就直连到那个地址。这个改动只对你自己生效，别人拿到的还是真的地址。

## 4.5 解析记录表上的几种记录

这些记录在哪儿填。你买域名那家的网站上，进去找“域名解析”“DNS 管理”或者“解析设置”，不同厂商叫法不同。打开以后是一张列表，一行一条记录。

你在后台看到的这张列表，会同步到权威服务器上，成为别人问这个名字时拿到的答案。你看到的是一个编辑界面，真正被查询的是另一头。

有个地方容易走错。域名注册商和 DNS 托管商可以不是同一家。域名在 A 公司买，解析托管给 B 公司，改记录就得去 B 公司的控制台，A 公司那边只会告诉你名字服务器已经指向别处。这是“我明明改了却没生效”的另一个来源。

一行记录至少要填四样东西。

| 格子 | 填什么 | 例子 |
| --- | --- | --- |
| 主机记录 | 名字的前半截 | `www`、`blog`，`@` 表示域名本身 |
| 记录类型 | A、AAAA、CNAME、TXT | `A` |
| 记录值 | 一个地址，或者另一个名字 | `203.0.113.24` |
| TTL | 缓存多少秒，一般留默认 | `600` |

所以“加一行”就是在那个页面上点“添加记录”，把这几个格子填上。比如要让 `blog.example.com` 指向 `203.0.113.24`，主机记录填 `blog`，类型选 `A`，值填 `203.0.113.24`，TTL 不动。

一条典型的配置是下面两行。第一行让 `example.com` 指向那台机器，第二行让 `www.example.com` 跟着 `example.com` 走。两条都配上，用户输哪个都能打开。

| 主机记录 | 记录类型 | 记录值 | TTL |
| --- | --- | --- | --- |
| `@` | `A` | `203.0.113.24` | `600` |
| `www` | `CNAME` | `example.com` | `600` |

主机记录只是名字，没有技术含义。`www` 来自老网站的习惯，`blog` 就是随手起的，两者在 DNS 眼里没有区别，真正决定指向哪里的是记录值。所以 `www.example.com` 和 `blog.example.com` 可以指向完全不同的两台机器，也可以指向同一台。

有两个名字值得单独记。`@` 代表域名本身，填了它，别人访问 `example.com` 才有答案。它只占主机记录这一格，类型和值照常填，上面表里的第一行就是。有的平台允许这格留空，效果一样，有的要求必须写出来。

反过来，在这里填整个 `example.com` 是不对的。有的平台会直接报错，有的会把它拼成 `example.com.example.com`，解析自然不生效。看到“改了没反应”，可以先回头看这一格。

`*` 是泛解析，凡是没有单独列出的子域名都走这一条，省事，但也容易把不该暴露的名字一起暴露出去。

还有一个常见的翻车点。只配了 `www` 没配 `@`，用户输 `example.com` 打不开，输 `www.example.com` 才行。反过来也一样。稳妥的做法是两个都配上，让其中一个用 301 跳到另一个。

还有两条限制值得知道。同一个名字可以有多条 `A` 记录，DNS 轮流返回，这是最原始的负载均衡。但同一个名字不能有两条 `CNAME`，那会冲突。

另外根域名按协议不能用 `CNAME`。要给 `example.com` 上 CDN，得用厂商提供的 ANAME、ALIAS 这类写法，或者直接给 CDN 的地址配 `A` 记录。

常见的有四类。

| 类型 | 作用 | 例子 |
| --- | --- | --- |
| A | 名字指向一个 IPv4 地址 | `example.com` → `203.0.113.24` |
| AAAA | 名字指向一个 IPv6 地址 | `example.com` → `2001:db8::1` |
| CNAME | 名字指向另一个名字 | `www.example.com` → `example.com` |
| TXT | 一段文本，用来做验证 | 证明这个域名是你的 |

A 记录最常用。CNAME 是别名，好处是主域名换了 IP，别名不用跟着改。TXT 你多半是在申请证书或者验证域名所有权的时候见过。

## 4.6 一个被误解的地方

域名不“包含”网站。它只是地址簿上的一行。

同一个域名可以指向一台服务器，也可以指向另一台，还可以指向一个负载均衡器。指向哪里，是你填的。网站打不开的时候，域名可能完全正常，问题在后面那一段。

反过来，一台服务器可以挂好几个域名。nginx 收到请求时会看请求头里的 `Host`，也就是用户访问的是哪个域名，然后决定给哪个网站的内容。这叫虚拟主机，第十二章会再遇到。

## 4.7 自己骗自己一下

本机有个文件叫 hosts，位置在 `/etc/hosts`，Windows 上是 `C:\Windows\System32\drivers\etc\hosts`。它是一本本地黄页，优先级比任何 DNS 都高。

在里面加一行。

```text
127.0.0.1  api.myapp.test
```

从此你访问 `api.myapp.test`，浏览器会去连本机。这招在开发时非常好用，因为你可以让本地代码以为自己在访问正式域名，避免改来改去。改完记得删，不然半年后你会忘了这件事，然后困惑一整天。

## 4.8 备案这件事

如果你的服务器在中国大陆，域名要对外提供网站服务，通常需要备案。没备案的域名解析到大陆机房的 80 和 443，会被拦掉。

这个拦截发生在运营商那一层，你机器上的日志里什么都看不到，服务是好的，端口是通的，就是外面访问不了。很多人在这里耗掉一整天。

判断方法很简单，换个非 80 端口试试，比如 `http://example.com:8080`。如果通，说明就是这个原因。港澳台和海外的服务器没有这个要求。

> **这一章记住一句**
>
> DNS 只负责把名字换成地址，它不负责那个地址上有没有人。
