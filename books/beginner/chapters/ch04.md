# 连不上的时候，按这个顺序看

## 4.1 先分清是哪种“连不上”

“连不上”是一句很模糊的话。实际遇到的，通常是下面四种之一，各自的含义完全不同：

| 现象 | 大概意思 |
| --- | --- |
| 提示找不到主机（`Could not resolve hostname`） | 名字没换成地址，是 DNS 的问题 |
| 一直转圈，最后超时（`Connection timed out`） | 包发出去没有回应，路不通或被拦了 |
| 马上被拒绝（`Connection refused`） | 到达了机器，但那个端口上没程序在听 |
| 提示认证失败（`Permission denied`） | 网络通了，是账号、密码或密钥不对 |

这四种现象，对应四个完全不同的方向。先判断属于哪一种，再往下查，能省掉一大半时间。

## 4.2 第一步：名字能不能换成地址

如果命令里用的是域名，先确认它能不能解析：

```bash
nslookup server.example.com
```

有结果，说明 DNS 没问题，继续下一步。没结果或者报错，就是 DNS 的问题：域名写错了、解析还没生效、或者你这台机器配置的 DNS 服务器不可用。

这一步的意义是：把“名字”这个变量排除掉，后面都用地址来测。

## 4.3 第二步：能不能找到并碰到那台机器

```bash
ping 198.51.100.17
```

ping 会发一个很小的包，看对方回不回。回了，说明路通、机器活着；不回，也不一定就是不通——有些服务器会故意不回应 ping。

所以更可靠的办法是直接测端口：

```bash
nc -vz 198.51.100.17 22
```

它只做一件事：试着连 22 端口，看能不能连上。

- 成功：端口是开的，路也通
- 超时：路上有东西把它拦了，或者地址根本不对
- 拒绝：机器在，但 22 端口没有程序在听

## 4.4 第三步：登录过程卡在哪

网络通了，还是登不上，就要看登录过程本身：

```bash
ssh -v alice@198.51.100.17
```

`-v` 会打印出连接的每一步：找到地址、建立连接、协商参数、验证身份、打开会话。哪一步停下，问题就在哪一步。

常见的有两种：

- 提示 `Permission denied (publickey)`：服务器不接受你的钥匙。可能是公钥没装到服务器上，可能是私钥文件不对，也可能是文件权限太松（第五章会讲）
- 卡在 `Authenticating` 很久：网络时通时断，或者服务器在等某个验证步骤

## 4.5 一张排查的顺序表

把上面的步骤串起来，就是一张顺序表：

1. `nslookup` —— 名字能不能换成地址
2. `ping` —— 那台机器活不活（不回应不代表死了）
3. `nc -vz 主机 端口` —— 那个端口开不开
4. `ssh -v` —— 登录过程卡在哪一步
5. 看日志 —— 服务器那边的记录

顺序不能乱。比如端口都没通，就去改密码，等于白忙。

还有一件事要记住：你手里的报错，往往来自链路上某一层，而不是最终的服务。比如浏览器说“连接被重置”，可能是公司网络里的设备干的；`502` 可能来自反向代理，而不是你写的程序。

## 4.6 这一章的三句话

- 先分清四种现象：解析失败、超时、拒绝、认证失败，方向完全不同。
- 排查按顺序：名字、机器、端口、登录，一步通了再走下一步。
- 报错可能来自中途某一层，别一上来就怀疑自己的代码。
