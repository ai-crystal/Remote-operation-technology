# 一次请求的完整旅程

> 排错不是猜，是找出第一个断掉的箭头。

这一章不讲新东西，只把前面十二章串成一条线。看懂这张图，前面那些概念就各自有了位置。

## 13.1 场景

你在咖啡馆，打开笔记本，在浏览器里输入 `https://myapp.com/api/hello`，回车。三秒钟后页面上出现一个 JSON。这三秒里发生了很多事。

先说清一件事：这一章的场景是**你自己搭的服务**。域名 `myapp.com` 是你的，证书是你配的，前面那台 nginx 是你装的，`127.0.0.1:8000` 上跑的程序也是你写的。所以每一站坏了，你都有权限登录上去看、去改。

访问别人的网站时，前三站（DNS、握手、TLS）你依然会经过，但机器不属于你，后面几站只能靠现象猜。排错时能看多深，取决于你能碰到哪一层。

## 13.2 从头走一遍

![图 13-1　一次访问的六个阶段](../images/13/fig13_1.png)

这六步细分成十站。下面一站一站走，每一站都告诉你它坏了是什么样子。

**第一站，DNS。** 浏览器问你家的运营商，`myapp.com` 是多少。拿到一个 IP。这一步失败的表现是“找不到服务器”或者 `Could not resolve hostname`。第四章。

**第二站，TCP 握手。** 浏览器向那个 IP 的 443 端口发起连接，三次握手。这一步失败是超时或者拒绝。第五、六章。

**第三站，TLS 握手。** 浏览器说我要访问 myapp.com，服务器拿出证书，浏览器验证签发机构、域名、有效期，然后双方协商密钥。这一步失败浏览器会显示证书错误，红色的警告页，不是 nginx 的错误页。

**第四站，HTTP 请求。** 加密通道建好，浏览器把请求发进去。就几行文本。

```text
GET /api/hello HTTP/1.1
Host: myapp.com
User-Agent: ...
```

**第五站，安全组。** 包到云厂商的边界，要过安全组的规则。没放行就丢在这里，表现是超时，机器上的日志什么都没有。第六章。

**第六站，系统防火墙。** 包进了机器，还要过 ufw 或 firewalld。表现同样是超时，但这次机器上的 `tcpdump` 能看到包进来了。

**第七站，nginx。** 它守着 443，看请求头里的 `Host` 是哪个域名，看路径是 `/api/hello`，找到对应的 `server` 块和 `location`，然后按配置转给 `127.0.0.1:8000`。

**第八站，你的程序。** 就是你在服务器上监听 `127.0.0.1:8000` 的那个进程，比如用 Python、Node 或 Go 写的后端。它收到请求，解析路径，跑业务逻辑，可能查一次数据库，把结果拼成 JSON。

**第九站，返回。** 原路返回，nginx 加上几个响应头，加密，发回浏览器。

**第十站，浏览器渲染。** 到这里才轮到前端代码。

## 13.3 每一步坏了长什么样

这张表是全书最实用的东西。遇到问题先在这里对一下症状。

| 你看到的现象 | 大概断在第几站 | 去哪儿查 |
| --- | --- | --- |
| 浏览器说找不到服务器 | 1，DNS | `nslookup myapp.com` |
| 一直转圈然后超时 | 2、5、6，连接没建立 | 先 `nc -vz IP 443`，再查防火墙 |
| 立刻说拒绝连接 | 2，端口没人听 | `ss -lntp` 看谁在 443 |
| 证书错误、红色警告 | 3，TLS | 证书域名、有效期、是否过期 |
| 502 Bad Gateway | 7 转 8，后端没人 | 程序是否在 8000 上监听 |
| 504 Gateway Timeout | 8，后端太慢 | 应用日志，是不是卡在数据库 |
| 413 | 7，nginx 限制 | `client_max_body_size` |
| 500 | 8，程序报错 | 应用日志，找堆栈 |
| 页面能开但样式全丢 | 8 之后的静态资源 | 路径、CDN、静态文件配置 |
| 能开但很慢，别的网站正常 | 8，业务逻辑或数据库 | 慢查询、外部接口 |

## 13.4 怎么用这张图

遇到问题的时候，不要从代码开始看，也不要凭直觉改配置。先问自己一句，现在断在第几站。判断方式是从两头夹。外面能看到什么，里面能看到什么。

外面报超时，里面 `ss -lntp` 看到端口在听，说明断在第五或第六站。里面日志里连请求记录都没有，也印证这一点。里面日志里有请求，说明已经过了第七站，问题在第八站。这个夹逼的过程每做一次就缩小一半范围，通常三四次就能定位。

## 13.5 一个心态

网络问题让人烦躁，是因为它不像代码报错那样给你一个行号。它给你的是一个现象，而且这个现象可能由五层里的任何一层造成。

但它的好处是，层与层之间的边界很清晰。每一层都有办法独立地测试。会测的人十分钟定位，不会测的人改一天配置，最后碰巧好了，还不知道为什么好。那张图贴在显示器边上，比记住一百条命令有用。

> **这一章记住一句**
>
> 先确定断在第几站，再决定改什么。
