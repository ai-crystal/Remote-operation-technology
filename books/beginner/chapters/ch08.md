# 第一次敲下 ssh

> 登录成功之后，你的键盘就长在服务器上了。

## 8.1 那行命令

AI 让你登录服务器，丢给你一行东西。这一行要在你自己的电脑上敲，不是在服务器上。

```bash
ssh root@203.0.113.24
```

你复制，粘贴，回车。终端里冒出一堆英文，然后跳出一句问你要不要继续连接。你输入 `yes`，接着它要密码。输完之后，提示符变了，从你熟悉的路径变成了一个陌生的。

```text
root@iZuf6h:~#
```

从这一刻起，你敲的每一条命令都在那台机器上执行。这一点是新手最容易忽略的。你以为自己在翻自己电脑的文件夹，其实翻的是几千公里外一台机器的目录。

## 8.2 SSH 是什么

SSH 的全称是 Secure Shell，直译过来是安全的壳。壳指的是 shell，终端里那个能敲命令的东西。安全指的是这条连接上的所有内容都加了密。别人在中间截获了数据，看到的是一堆乱码。

在它之前，大家用的是 telnet。telnet 把你说的话原样发过去，包括密码。任何一个能在你线路上抓包的人，都能看到你的密码。这件事在九十年代被反复利用，于是有了 SSH。

今天的 SSH 是 OpenSSH 这个实现，几乎所有 Linux 和 macOS 自带，Windows 10 以后也内置了。你在 Windows 的 PowerShell 里直接敲 `ssh` 就能用，不需要装 PuTTY。

它有一个服务端，叫 sshd，跑在目标机器的 22 端口上，等着你连。还有一个客户端，就是 `ssh` 这个命令，跑在你的电脑上。

## 8.3 把命令拆开看

```bash
ssh -p 2222 -i ~/.ssh/myserver alice@203.0.113.24
```

`-p 2222` 告诉 ssh 客户端，去敲服务器的哪一扇门。门后面站着的是 SSH 服务，它自己有一个端口，默认 22。这个数字由那台机器决定，不是 ssh 命令决定的。多数云镜像保持 22；有的厂商或运维会改成 2222 这种不常见的数字，因为 22 每天会被扫描器敲几万次。改成多少，要去**服务器**上看 `/etc/ssh/sshd_config` 里的 `Port`（或者 `ss -lntp` 里 sshd 的那一行）；云控制台的实例信息里不写这个，问给你机器的人最快。

它只管 SSH 这一条，跟这台机器上其他服务无关。同一台服务器上，SSH 在 2222 等你，nginx 在 443 等你，你的程序在 8000 等你，三扇门各走各的。你在浏览器里访问网站，走的是 443，不会因为 SSH 换成了 2222 而受影响。

顺带提醒，`-p` 这个字母在不同命令里意思不一样。`ssh` 的 `-p` 是端口，`scp` 的端口是大写 `-P`，`docker` 的 `-p` 是“把容器端口放到宿主机上”。三个都叫 p，干的不是一件事。

`-i ~/.ssh/myserver` 指的是用哪一把私钥。私钥有两个常见来路。一是你自己用 `ssh-keygen` 生成的，`myserver` 只是你起的文件名，第九章讲。二是买机器时厂商给你的那个 `.pem` 文件，创建实例时下载一次，之后不再提供。不管哪种，它都在你自己的电脑上，不在服务器上。

不写 `-i` 的话，ssh 会去 `~/.ssh/` 里按默认名字找，比如 `id_ed25519`、`id_rsa`。所以自己生成的密钥如果用了默认名字，这一项可以省掉。

`alice` 是你在那台机器上的用户名。`root` 是管理员，`ubuntu` 是 Ubuntu 镜像默认的用户，`ec2-user` 是亚马逊的。用错用户名的报错是 `Permission denied`，看起来像密码错了，其实是你找错了人。`@` 后面是地址或者域名。

## 8.4 第一次连接时那个问题

```text
The authenticity of host '203.0.113.24' can't be established.
ED25519 key fingerprint is SHA256:9f2c1d....
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

它在问的是，你确定这台机器真的是你要连的那台吗。因为 SSH 是加密的，加密需要一个对方的身份。第一次见面的时候，它没有记录，只能让你自己确认。你确认之后，它会把这个指纹记在 `~/.ssh/known_hosts` 文件里。下次再连，它会比对，一致就直接连，不一致就报警。

这个机制叫首次信任，英文缩写 TOFU。它假设你第一次连的时候环境是干净的，这个假设不总是成立，但在日常使用里够用。

如果你看到红色的 `REMOTE HOST IDENTIFICATION HAS CHANGED`，意思是这个地址的指纹变了。可能是服务器重装了系统，也可能是有人在中间冒充。前者常见，后者严重。你要做的是先确认，如果确实是自己重装了，用 `ssh-keygen -R 203.0.113.24` 把旧记录删掉再连。

## 8.5 登录之后的世界

有几个概念值得立刻建立。你的命令在那台机器上执行，而不是在本地。所以你 `cd` 进一个目录，是服务器的目录，关掉窗口下次登录就回到了默认位置。

每个终端窗口是一个独立会话。你在 A 窗口 `cd` 到别处，B 窗口还在原处。你在 A 窗口里跑的程序，关掉 A 就跟着结束了，这个坑在第十一章专门讲。

你退出的方式是 `exit`，或者 `Ctrl+D`。断网也算退出，但程序可能还活着，也可能不活着，取决于它怎么跑的。

## 8.6 一个格式上的提醒

`ssh alice@host` 后面可以跟一条命令。

```bash
ssh alice@203.0.113.24 "uptime"
```

这条命令执行完就断开，不会给你一个交互的终端。它常常出现在脚本里，也常常出现在排错时，因为它比登录进去再看要快。

很多 AI 给的排错步骤会用这种写法。你要知道它和登录进去敲的区别，前者是一次性的，环境变量和当前目录都可能跟你想象的不一样。第十章和第十四章会再提到这个差别带来的问题。
