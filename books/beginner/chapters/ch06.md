# 钥匙：为什么不用密码也能登录

## 6.1 密码的两个麻烦

用密码登录很直观：报账号，输密码，服务器核对。但它有两个麻烦。

第一，密码会在网络上传输。如果通道没加密，路过任何一台设备都可能看到（第二章讲过的 telnet 就是这样）。SSH 虽然会加密，但密码本身仍然是“可以被偷、可以被猜”的东西。

第二，密码可以被撞。有人拿一批常见的密码，挨个账号试，试到你为止。公网上的服务器每天都会被这样扫。

所以更稳妥的方式是：不用密码，用钥匙。

## 6.2 一对钥匙，一把给别人看

钥匙登录用的是一对：一把叫**私钥**，一把叫**公钥**。

- 私钥：只放在你自己的电脑上，谁都不给，文件权限必须是 600
- 公钥：可以随便发，装到服务器上也没关系

服务器上有一个文件叫 `authorized_keys`，里面列着“允许登录的公钥”。你把自己的公钥放进去，服务器就认识你了。

登录的时候，服务器不会问你要密码，而是给你出一道题：你用私钥对一段数据“盖个章”，它用你给它的公钥验一下。验过了，就证明你手里确实有那把私钥。

图 6-1 是这件事的示意。

这里有一个方向别记反：**私钥用来盖章（签名），公钥用来验章**。加密的方向是另一回事，本书不展开。

私钥从头到尾没有离开过你的电脑，服务器上也从来没有过它。所以就算服务器被攻破，攻击者拿到的也只是公钥。

## 6.3 第一次连接，你在信任什么

第一次连一台陌生的服务器，会看到这样一句提示：

```text
The authenticity of host '198.51.100.17' can't be established.
ED25519 key fingerprint is SHA256:9f2c1d...
Are you sure you want to continue connecting (yes/no)?
```

它在说：我没见过这台机器，不能确定对面是不是真的。它给你看一个**指纹**，也就是那把公钥算出来的一个短字符串。

你回答 yes 之后，这个指纹会被记到本机的一个文件里，叫 `known_hosts`。以后每次连接，客户端都拿服务器出示的公钥和记录比对：一致就通过，不一致就报警并拒绝连接。

这套做法叫“首次使用即信任”。它的意思是：第一次你没有别的办法核实，只能选择相信；之后靠记住来发现变化。

指纹变了有两种可能：服务器重装了，换了主机密钥；或者真的有人在中间冒充。客户端分不清，只能停下来问你。**不要条件反射地删掉记录**，先问清楚。

## 6.4 自己动手：三分钟配好钥匙登录

在自己的电脑上生成一对钥匙（一路回车即可）：

```bash
ssh-keygen -t ed25519 -C "alice@laptop"
```

它会在 `~/.ssh/` 下生成两个文件：`id_ed25519`（私钥）和 `id_ed25519.pub`（公钥）。

把公钥装到服务器上：

```bash
ssh-copy-id alice@198.51.100.17
```

然后直接 `ssh alice@198.51.100.17`，应该不再问密码。

如果还要输密码，按第四章的顺序查：`ssh -v` 会告诉你卡在哪一步，最常见的是公钥没装对，或者私钥权限太松。

## 6.5 这一章的三句话

- 钥匙登录用一对：私钥自己留，公钥装到服务器的 `authorized_keys` 里。
- 登录时用私钥签名、服务器用公钥验签，私钥从不离开你的电脑。
- 第一次连接看到指纹是在提醒你“还没法核实”，记住之后靠它发现变化。
