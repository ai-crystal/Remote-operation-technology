# 门牌号和房间号

> 一台服务器只有一个门牌号，却能同时开十几个窗口。

第二个项目要跑起来的时候，终端里冒出一行红字。

```text
OSError: [Errno 98] Address already in use
```

你把启动命令里的 `8000` 改成 `8001`，好了。你不知道刚才发生了什么，只知道数字改大一点就通了。

## 2.1 一个地址，很多扇门

一台服务器通常只有一个公网 IP。可它在同时干很多事。有人在上面登录，有个网站在对外提供服务，有个数据库在等查询，可能还有个定时任务在跑。一个地址怎么区分这些事。答案是端口。

IP 负责把数据送到这台机器，端口负责说明这份数据是给机器上哪个程序的。门牌号加房间号，缺一不可。

端口是一个数字，范围从 0 到 65535。它不是物理存在的洞，也不是网线接口。它是操作系统内核里的一张登记表上的一行。一个程序想在网络上被找到，得先向系统申请一个端口，系统在表上记一笔，从此送到这个端口的连接就交给它。申请成功叫监听。这两个字很形象，程序坐在那个窗口后面等，有人来就连上。

## 2.2 那张表上写了什么

```bash
ss -lntp
```

这条命令在哪台机器上敲，就列出哪台机器的端口。书里的例子是在服务器上敲的，所以能看到 `sshd`、`nginx` 这些。输出大约长这样。

`sshd` 是远程登录的服务端，`nginx`（读作 engine-x）是服务器上常见的一个网页服务器软件，站在最外面替后面的程序接待请求，第十二章会专门讲它。

```text
State   Local Address:Port   Process
LISTEN  0.0.0.0:22           sshd
LISTEN  0.0.0.0:443          nginx
LISTEN  127.0.0.1:8000       python
LISTEN  127.0.0.1:3306       mysqld
```

四个服务，一台机器，互不打扰。数据到了 443 归 nginx，到了 22 归 sshd。

## 2.3 几个数字要认得

| 端口 | 通常是谁 | 说明 |
| --- | --- | --- |
| 22 | SSH | 远程登录用的 |
| 80 | HTTP | 明文网页 |
| 443 | HTTPS | 加密网页 |
| 3306 | MySQL | 数据库，用表存数据 |
| 5432 | PostgreSQL | 数据库，另一种常见的开源数据库 |
| 6379 | Redis | 缓存，把数据放内存里加速读取 |
| 3000、5000、8000、8080 | 各种开发服务器 | 没有统一规定，谁先占谁用 |

前面那些数字是行业习惯，不是法律。你可以把网站放在 8080，只不过别人访问的时候得把端口写上。浏览器默认去 443，所以正式网站一般不写端口。

1023 以下的端口有个额外规矩，普通用户不能占用，需要管理员权限。这是几十年前留下的约定，那会儿这些端口专门留给系统服务。所以你启动一个要绑 80 端口的程序，会看到 `Permission denied`，那不是文件权限问题，是端口权限问题。

## 2.4 为什么不能两个程序用同一个端口

因为数据到了之后没法分。一份连接进来，端口 8000，系统只能把它交给一个程序，交错了就是串台。

所以 `Address already in use` 的意思很直接，这个窗口已经有人坐着了。你要么把坐着的人请走，要么换个窗口。请走的办法是找到它然后结束它。

```bash
ss -lntp | grep 8000
kill <那个进程的 PID>
```

但更多时候，换一个窗口更省事。开发的时候端口随便挑，别去抢 80 和 443 就行。有一个细节值得知道，同号端口可以绑在不同的地址上而不冲突。`127.0.0.1:8000` 和 `192.168.1.23:8000` 可以同时存在，因为它们收的是不同网卡上的数据。但 `0.0.0.0:8000` 会跟它们都冲突，因为 `0.0.0.0` 的含义是“所有网卡”，所有里面包含了那两个。下一章专门说这件事。

## 2.5 端口开了，不等于门开了

这是新手最容易混的一处。“开端口”在日常说话里指两件完全不同的事。一件是程序在监听，另一件是防火墙允许数据进来。两件都做到，外面才连得上。

只做了第一件，外面的包会被防火墙丢掉，你看到的是超时。只做了第二件，包能进来但没人接，你看到的是拒绝。两件都做错了，你什么都看不到，浏览器转圈转到自己放弃。这三种失败长得不一样，含义也不一样。

| 你看到的 | 真实情况 | 先查什么 |
| --- | --- | --- |
| `Connection refused` | 包到了机器，但这个端口没人监听 | 程序起了吗，端口号对吗 |
| `Connection timed out` | 包根本没到，或者被中途丢了 | 防火墙、云安全组、地址对吗 |
| 连上了但一直没回应 | 端口有人，但程序卡住了或者不说话 | 程序日志，它是不是在等别的资源 |

会区分这三种，你的排查速度会快一个数量级。因为 refused 是应用层的问题，timeout 是网络层的问题，它们该去的地方完全不同。

> **这一章记住一句**
>
> 端口是程序在机器上登记的窗口号，一个窗口同一时间只能坐一个人。

下一章讲那个让无数人栽跟头的写法，`0.0.0.0`。它看起来只是把地址换了个数字，实际含义差着一条街。
