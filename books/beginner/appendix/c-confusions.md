# 附录 C　长得像，但不是一回事

　　下面这些写法，屏幕上看只差一个字符，含义却完全不同。初学时的多数误操作，都出在这几对上。

| 一对写法 | 分别是什么 | 什么时候会混 |
| --- | --- | --- |
| `ssh -p 2222` 与 `scp -P 2222` | 都是指定端口，`ssh` 用小写 `-p`，`scp` 用大写 `-P` | 输错了不报参数错误，而是连默认 22 端口然后超时（第 15 章） |
| `127.0.0.1` 与 `localhost` | 前者是回环地址，后者是指向它的名字 | 名字可能先解析到 IPv6 的 `::1`，程序只监听 IPv4 时会连不上（第 3 章） |
| `0.0.0.0` 与 `0.0.0.0/0` | 前者是“本机所有网卡都监听”，后者是“任何来源地址” | 一个写在程序参数里，一个写在安全组规则里，位置完全不同（第 3.6 节） |
| 端口 `0` 与端口 `8080` | 申请 `0` 表示“让系统随便分一个空闲端口” | 看到日志里出现 30000 多的大号端口，多半是用 `0` 换来的（第 2 章） |
| `id_ed25519` 与 `id_ed25519.pub` | 前者是私钥，后者是公钥 | 把 `.pub` 当私钥用会报 `invalid format`（第 9 章） |
| `authorized_keys` 与 `known_hosts` | 前者在服务器上，列“谁能进来”；后者在你电脑上，记“我去过谁” | 两者都在 `~/.ssh/` 下，删错了后果相反（第 9、10 章） |
| `ssh_config` 与 `sshd_config` | 前者是你电脑上的客户端配置，后者是服务器上的服务端配置 | 把服务端选项写进客户端文件，通常不报错，只是静默失效（第 10 章） |
| `systemctl restart` 与 `systemctl reload` | restart 停掉再启动，连接会断；reload 重新读配置，服务不停 | 改完 nginx 配置用 restart，会把正在处理的请求打断（第 11、12 章） |
| `chmod 600` 与 `chmod 644` | 600 只有本人能读写；644 其他人也能读 | 私钥用 644 会被 `ssh` 拒绝；公钥用 600 没有坏处但没必要（第 10 章） |
| `401` 与 `403` | 401 是“没认证”，403 是“认证了但没权限” | 客户端处理方式不同：一个去登录，一个去申请权限（第 17 章） |
| `502` 与 `504` | 502 是“连不上后端”，504 是“连上了但等太久” | 一个查进程和端口，一个查慢查询和外部接口（第 13 章） |
| `kill` 与 `kill -9` | 前者发终止信号，程序可以清理后退出；后者强制杀死 | 一上来就用 `-9`，日志和临时文件都来不及收拾（第 2 章） |
| `docker -p 8000:8000` 与 `-p 127.0.0.1:8000:8000` | 前者映射到宿主机所有网卡，后者只映射到回环 | 前者等于把这个端口暴露给能到达这台机器的所有人（第 3 章） |
| `scp` 与 `rsync` | 前者整份拷贝，后者只传变化的部分 | 传大文件、反复同步时差别明显（第 15 章） |

　　看的时候可以记一条：**差别在“谁来配置”和“配在哪一层”**。同一个数字、同一个词，写在程序里、写在服务器配置里、写在云控制台里，作用范围完全不同。分不清时，先问“这一行是谁读的”。
